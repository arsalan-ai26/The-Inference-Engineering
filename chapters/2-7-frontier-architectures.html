Frontier architectures and research

The standard transformer has two costs that grow with use: the KV cache grows with every token, and decode makes one serial pass per token. A wave of new designs attacks these costs: state-space and linear-attention layers, hybrids, diffusion language models, and new ways to spend compute at test time. This chapter explains each one by the single question an inference engineer must ask: what does it change in memory, compute and latency?

Before you start: what you should already know

This is an expert-depth chapter. You need the KV cache formula (chapter 2.4), the memory-bound nature of decode (chapter 2.5) and MoE (chapter 2.6). Every section ends with an "inference impact" line so you can skim.

1. Why architectures keep changing

From chapters 2.2 to 2.5, a standard decoder-only transformer has three scaling problems for serving:

  1. Memory grows with context. The KV cache is linear in tokens. At 1M tokens, even an efficient model needs tens of GB per sequence.
  2. Prefill attention is quadratic. Doubling a long prompt quadruples attention work.
  3. Decode is serial and memory-bound. One token per pass, each pass reading all the weights.

Problems 1 and 2 grow worse as agents and reasoning models use longer and longer contexts. Problem 3 sets a floor on time per token. Each design in this chapter attacks one or more of them, and each pays for it somewhere else.

2. State-space models and linear attention

Recall the RNN of chapter 1.5: a fixed-size state updated once per token. It was abandoned because it forgot, and because training could not run in parallel over the sequence. Two ideas brought it back:

  • Linear recurrences can be computed in parallel. If the update is linear in the state (h_t = A_t h_{t−1} + B_t x_t), the whole sequence can be computed with a parallel scan or in chunks, like attention. So training and prefill are fast.
  • The update can depend on the input. "Selective" state-space models (Mamba) and gated linear attention (Gated DeltaNet, Kimi Delta Attention) let each token decide what to write into the state and what to forget. This fixed much of the old forgetting problem.

Linear attention arrives at the same place from the attention side. Remove the softmax from attention and the sum Σ v_j k_jᵀ can be kept as a running matrix: a fixed-size state of shape [d_k, d_v] per head. Each new token adds its own outer product. Reading is one matrix-vector product with the query.

state_t = decay_t ⊙ state_{t−1} + v_t k_tᵀ output_t = state_t q_t
Inference impact

Memory per sequence is constant, whatever the context: a few MB per sequence instead of a cache that grows. Decode cost per token is constant too: no attention over n past tokens. The price is recall: a fixed-size state cannot store every detail of a million tokens, so pure linear models are weaker at exact retrieval ("what was the number on page 3?").

3. Hybrids: mostly linear, some full attention

The current answer is to mix both. Most layers are linear (cheap, constant state), and every few layers is a full-attention layer (exact recall, growing KV cache). Several 2025 open models use a 3:1 pattern:

Inference impact

A 3:1 hybrid cuts the KV cache about 4 times and keeps exact recall through its attention layers. Engines must now manage two kinds of per-sequence memory: a paged KV cache for the attention layers and a fixed state slot for the linear layers. Two features get harder: prefix caching (chapter 4.4), because you cannot slice a recurrent state at an arbitrary earlier token unless you saved a checkpoint there, and speculative decoding (chapter 4.3), because rejected tokens have already been folded into the state and must be undone. Engines such as vLLM added a hybrid cache manager for this (chapter 3.3).

4. Diffusion language models

All models so far generate left to right, one token per pass. A diffusion language model generates differently:

  1. Start with a block of N positions, all masked (unknown).
  2. Run the model on the whole block. It predicts a token for every masked position at once.
  3. Keep the most confident predictions; leave the rest masked.
  4. Repeat for a fixed number of steps until no masks remain.

The attention is bidirectional within the block, so each pass sees the whole draft. Research models such as LLaDA (8B) and commercial systems such as Inception's Mercury use this approach. Block diffusion mixes both worlds: blocks are produced left to right (so earlier blocks can be cached), and tokens inside each block are produced by diffusion.

Interactive: serial passes, autoregressive vs diffusion
How many forward passes it takes to write N tokens, and a rough time estimate. An autoregressive pass is memory-bound (reads all weights for one token per sequence). A diffusion pass processes a whole block, so it does far more math per weight read.

Assumes an 8B BF16 model on one H100: an autoregressive pass ≈ 4.8 ms (memory-bound, chapter 2.5); a diffusion pass over a block of B tokens ≈ max(4.8 ms, compute time of 2 × 8 B × B FLOPs at 50% MFU). Illustrative; real systems add caching and other tricks.

Inference impact

Diffusion trades many cheap serial passes for fewer, heavier parallel passes. Each pass is compute-bound rather than memory-bound, which uses the GPU better at small batch and can cut latency. The costs: quality depends on the number of denoising steps, the KV cache does not work inside a block that keeps changing, and serving engines and sampling controls are much less mature. Support is starting to appear (for example, an SGLang design proposal for block-diffusion serving).

5. Spending compute at test time

Reasoning models "think" before answering: they generate long chains of thought, often thousands of tokens. This changes the workload more than any architecture change:

  • Output tokens dominate. A request may be 500 input tokens and 10,000 output tokens. Decode, which is memory-bound, becomes nearly all the cost.
  • The KV cache grows during the answer. Long outputs fill memory just like long prompts.
  • Energy and cost per query rise. One 2025 study estimates a median of about 0.31 Wh per query for frontier-scale models on H100 nodes, rising about 13 times to 3.9 Wh when outputs are 15 times longer.

Research now looks for better ways to spend the same compute:

  • Parallel sampling. Generate several answers from one prompt and pick or vote. The prompt's KV cache is shared (chapter 3.3), so this uses batching well.
  • Parallel-Distill-Refine. Generate drafts in parallel, distill them into a short bounded workspace, refine, and repeat. Context stays short, so latency and memory stay bounded while accuracy rises.
  • Recursive language models. Instead of reading a huge context directly, the model works in a code environment (a Python REPL) holding the data, inspects pieces of it, and calls sub-models on small pieces. One giant request becomes many short ones.
Inference impact

Workloads become decode-heavy, long-horizon and multi-call. That favours systems with fast decode (high bandwidth, speculative decoding), good prefix reuse across many related calls, and schedulers built for agents (chapter 6.8). It also changes pricing: when an agent re-sends a growing context on every step, the cost of cached input tokens can grow with the square of the number of steps.

7. Expert layer

State precision

Recurrent states accumulate updates over millions of steps, so small rounding errors can build up. Some hybrid models keep the SSM state in FP32 even when the weights are BF16 (Nemotron 3 Nano's config sets mamba_ssm_cache_dtype to float32). Engines must honour this, or long outputs degrade.

Chunked algorithms

Linear attention and SSM layers in prefill run in chunks: inside a chunk, a small attention-like matmul (good for tensor cores); between chunks, the state is passed along. Choosing the chunk size balances parallel work against state traffic, the same trade-off as tiling in FlashAttention.

How to evaluate a new architecture as a serving engineer
  1. Write the per-token state: what grows with context, what stays fixed, in which precision.
  2. Write the serial steps per output token.
  3. Estimate decode bytes per step and prefill FLOPs per token (chapter 2.5).
  4. Check engine support: kernels, prefix caching, speculative decoding, quantization, parallelism.
  5. Check quality where your users need it: long-context recall, reasoning, tool use.

8. Common mistakes

  • Assuming linear-attention models are free at long context. Their state is fixed, but recall is limited, which is why hybrids keep some full attention.
  • Expecting prefix caching and speculative decoding to work the same on hybrid models.
  • Comparing diffusion and autoregressive models by "tokens per second" without matching quality and step counts.
  • Ignoring reasoning length when sizing a deployment. A reasoning model's average output can be 10 times a chat model's.
  • Treating a research result as production-ready before engines and quantization tools support it.

9. Lab

Goal: see that a linear recurrence has a parallel form, compare state and cache memory on real configs, and simulate a diffusion decoder.

Part A: one recurrence, two ways to compute it

import torch
torch.manual_seed(0)
T, dk, dv = 64, 16, 16
q, k, v = torch.randn(T, dk), torch.randn(T, dk) / dk**0.5, torch.randn(T, dv)
decay = torch.sigmoid(torch.randn(T)) * 0.2 + 0.8          # per-token forget gate in (0.8, 1.0)

# 1. Recurrent form (how decode runs): constant-size state
S = torch.zeros(dv, dk); out_rec = []
for t in range(T):
    S = decay[t] * S + torch.outer(v[t], k[t])
    out_rec.append(S @ q[t])
out_rec = torch.stack(out_rec)

# 2. Parallel form (how prefill can run): an attention-like matmul with a decay mask
logd = torch.log(decay).cumsum(0)
mask = torch.tril(torch.exp(logd[:, None] - logd[None, :]))   # product of decays between j and t
out_par = (mask * (q @ k.T)) @ v
print(torch.allclose(out_rec, out_par, atol=1e-4))
print("state size:", S.numel(), "values, whatever T is")

Change T to 4,096. The state is still 256 values; a KV cache for the same layer would hold 2 × 4,096 × 16 values. Then explain why the parallel form is used for prefill and the recurrent form for decode.

Part C: a toy diffusion decoder

import random
target = "the quick brown fox jumps over the lazy dog".split()
def toy_model(draft):            # pretend model: knows the answer, confidence is random
    return [(w, random.random()) for w in target]
def diffusion_decode(n_steps):
    draft = ["[M]"] * len(target)
    per_step = -(-len(target) // n_steps)      # ceil: tokens to unmask per step
    for step in range(n_steps):
        preds = toy_model(draft)
        masked = [i for i, w in enumerate(draft) if w == "[M]"]
        masked.sort(key=lambda i: -preds[i][1])  # most confident first
        for i in masked[:per_step]:
            draft[i] = preds[i][0]
        print(f"step {step+1}: {' '.join(draft)}")
diffusion_decode(3)

This toy shows only the control flow: several positions are filled per pass, in confidence order, not left to right. With 3 steps it needs 3 passes for 9 tokens; an autoregressive model needs 9. Real models make mistakes when too many tokens are unmasked per step, which is the quality-versus-steps trade-off.

10. In the real world

Where these designs stand
  • Hybrids with linear attention or Mamba layers are now shipped by several labs (Qwen, Moonshot, NVIDIA, AI21) and supported in major engines, often with dedicated kernels.
  • Diffusion LMs are offered commercially for low-latency code and text, but open serving support is early.
  • Reasoning models are mainstream; their long outputs are the main driver of decode demand.
  • Follow releases through engine release notes and model-specific serving recipes (chapter 3.7), which say what each new architecture needs.

12. Summary

  • Standard transformers have three serving costs that grow: KV memory, quadratic prefill, serial memory-bound decode.
  • SSMs and linear attention keep a fixed-size state: constant memory and per-token cost, weaker exact recall.
  • Hybrids (often 3 linear layers to 1 full) cut the KV cache about 4 times but complicate prefix caching and speculative decoding.
  • Diffusion LMs fill many positions per pass, trading serial memory-bound steps for fewer compute-bound ones.
  • Test-time reasoning makes workloads decode-heavy and long; new methods bound context while spending compute in parallel.
  • Evaluate any new design by its per-token state, serial steps, bytes and FLOPs, and engine support.
