Probability and sampling

A model does not output a word. It outputs a score for every token in its vocabulary. A small piece of code then picks one token from those scores. That code, the sampler, decides whether a reply is creative or repetitive, and whether two runs give the same text. This chapter shows exactly how it works.

  2. The first two. 0.5 alone is below 0.75; 0.5 + 0.3 = 0.8 reaches it.
  3. The numbers inside the model can change slightly with the batch size, because the GPU adds them in a different order. A tiny change can flip which token is largest.

1. From the model to a list of scores

The last layer of an LLM is a matmul (chapter 1.1) from the hidden size to the vocabulary size. For Llama 3.1 8B that is [4096] → [128256]. The output is one number per token in the vocabulary.

Definitions

Vocabulary: the full list of tokens the model knows. Chapter 2.1 explains how text becomes tokens.

Logit: the raw score the model gives one token. It can be any real number. A higher logit means "more likely next".

Probability distribution: a list of non-negative numbers that add up to 1. Each number is the chance of one outcome.

Logits are not probabilities. They can be negative, and they do not add up to 1. We need a function that turns them into a distribution but keeps their order.

2. Softmax: scores to probabilities

Softmax does two steps:

  1. Apply the exponential function to each logit: eᶻ. This makes every value positive, and it makes big logits much bigger than small ones.
  2. Divide each result by the sum of all results. Now they add up to 1.
pᵢ = e^(zᵢ) ÷ Σⱼ e^(zⱼ)
Worked example

Logits [2, 1, 0]. Exponentials: e² = 7.389, e¹ = 2.718, e⁰ = 1. Sum = 11.107.

Probabilities: 7.389 ÷ 11.107 = 0.665, 2.718 ÷ 11.107 = 0.245, 1 ÷ 11.107 = 0.090.

A gap of 1 in logits means a ratio of e ≈ 2.72 in probability. A gap of 5 means a ratio of about 148. This is why the top few tokens usually hold almost all the probability.

Only differences matter. Adding the same number to every logit does not change the result. Code uses this to avoid overflow: it subtracts the largest logit first, so the biggest exponent is e⁰ = 1. Every real softmax implementation does this.

The log-probability (logprob) of a token is the natural log of its probability. Logprobs are always 0 or negative. APIs can return them, and evaluation code adds them up, because adding logs is safer than multiplying many small probabilities.

3. Choosing a token: greedy, beam and sampling

With a distribution in hand, the generator must pick one token. Then it appends that token and runs the model again (the loop in chapter 2.4). Three families of strategy exist.

StrategyWhat it doesGood forProblem
GreedyAlways pick the highest-probability tokenShort factual answers, tests, extractionOften loops and repeats itself in long text
Beam searchKeep the best N partial sequences, extend each, keep the best N againTranslation, summarization with fixed lengthN times the compute; text is often bland; rarely used for chat
SamplingDraw a token at random, with each token's chance equal to its probabilityChat, creative writing, almost all assistant useCan pick a strange low-probability token unless you filter

Sampling is the default for chat models. The rest of this chapter is about controlling it with four knobs: temperature, top-k, top-p and min-p.

4. Temperature: sharpen or flatten

Temperature T divides every logit before the softmax:

pᵢ = softmax(z / T)ᵢ
  • T = 1: no change. You sample from the model's own distribution.
  • T < 1: gaps between logits grow, so the top token gets more probability. Output becomes more predictable.
  • T > 1: gaps shrink, so the distribution flattens. Output becomes more varied, and at high T it becomes nonsense.
  • T → 0: the top token gets all the probability. This is greedy decoding. APIs treat temperature 0 as greedy, because dividing by zero is not defined.

Analogy: the logits are the heights of hills. Low temperature is like cold weather: everything freezes into the deepest valley. High temperature shakes the landscape so a ball can land anywhere.

5. Truncation filters: top-k, top-p, min-p

Even at T = 1, the long tail of the vocabulary holds real probability. With 128,000 tokens, many tiny chances add up, and one bad pick can derail a reply. Filters cut the tail, then renormalize the survivors so they add up to 1 again.

FilterRuleWeakness
Top-kKeep the k highest-probability tokensk is fixed. When the model is sure, k = 50 still keeps 49 bad options. When it is unsure, 50 may be too few.
Top-p (nucleus)Sort by probability. Keep the smallest set whose probabilities add up to at least pAdapts to confidence, but at high temperature the flat distribution lets many weak tokens in.
Min-pKeep tokens whose probability is at least p × (probability of the top token)Newer; not available in every API.

Top-p adapts to the shape of the distribution. If the model is confident (top token 0.95), top-p 0.9 keeps one token. If it is unsure, it keeps many. Min-p also adapts, by tying the cut-off to the top token's probability.

Watch out: order matters

Libraries apply temperature, filters and penalties in a fixed order, and that order is not the same in every library. The same settings on two engines can give different distributions. When you compare engines, compare their sampling code too.

6. Penalties, biases and stop rules

A sampler has more controls than the four above. You will meet these in every API and engine:

  • Repetition penalty: divides the positive logits (and multiplies the negative ones) of tokens that already appeared, by a factor such as 1.1. Values above 1 discourage repeats.
  • Presence penalty: subtracts a fixed amount from the logit of any token that has appeared at least once.
  • Frequency penalty: subtracts an amount for each time a token has appeared, so frequent tokens get pushed down more.
  • Logit bias: adds a chosen value to specific tokens. A large negative value bans a token. Structured output (chapter 3.5) extends this idea: it masks every token that would break a JSON schema.
  • Stop conditions: generation ends at the end-of-sequence (EOS) token, at a stop string, or at max_tokens.
  • Seed: the start value of the random number generator. With the same seed, the same model and the same numbers, sampling picks the same tokens.
  • n: the number of separate completions for one prompt. The prompt is processed once and shared (chapter 3.3 shows how).

7. Why the same prompt can give different answers

Sampling is random by design, so different outputs at T > 0 are normal. The surprise is temperature 0. Many people see different outputs at T = 0 on a hosted API. The cause is not the sampler.

GPU floating-point addition is not perfectly associative: (a + b) + c can differ from a + (b + c) in the last bit. A matmul or normalization kernel can choose a different way to split and add its sums depending on the batch size. The batch size on a server depends on how many other users send requests at the same moment. So the logits of your request can change slightly with server load. If two top tokens are almost tied, the argmax can flip, and from that token on the text is different.

The fix is to make every kernel "batch-invariant": it must add numbers in the same order whatever the batch size. This is possible but costs some speed. Some engines now offer it as an option for work such as reinforcement learning, where exact repeats matter.

8. What sampling costs

Sampling runs once per generated token, for every sequence in the batch. Its cost is small next to the model, but not zero:

  • The output head matmul (hidden size × vocabulary size) is one of the largest single matmuls in the model. For Llama 3.1 8B it is 0.53 B parameters, about 6.5% of the model.
  • Softmax over 128,256 values is cheap. Top-p and top-k usually need the tokens in sorted order, and sorting 128,256 values per sequence per step takes real time at large batch.
  • Each request in a batch can have different settings. Engines apply all of them in one batched GPU operation.

9. Expert layer

Sorting-free sampling kernels

Sorting the vocabulary for top-p is slow on a GPU. Some kernel libraries avoid it with rejection sampling: draw a candidate, test it against a threshold, and repeat with an updated threshold until a candidate passes. The result has the same distribution as sort-then-sample, with much less work at large batch.

The Gumbel-max trick

Adding independent Gumbel noise to each logit and taking the argmax gives an exact sample from the softmax distribution. This turns sampling into "add noise, then take a max", which is easy to run in parallel.

Sampling and speculative decoding

Speculative decoding (chapter 4.3) lets a small model guess several tokens, and the large model checks them. A careful accept-or-reject rule makes the final output follow exactly the large model's sampling distribution. So you can speed up decoding without changing the output distribution.

Reasoning models and long outputs

Model makers often publish recommended sampling settings for each model, for example a specific temperature and top-p for "thinking" mode. Greedy decoding on some reasoning models leads to endless loops. Always read the model card before you choose settings.

10. Common mistakes

  • Thinking logits are probabilities. Apply softmax first.
  • Applying softmax without subtracting the max logit. Large logits overflow to infinity.
  • Expecting temperature 0 to be exactly repeatable on a shared server.
  • Setting both a low top-p and a low temperature, then wondering why output is repetitive. Each one already narrows the choice.
  • Forgetting to renormalize after a filter. The kept probabilities must add up to 1.
  • Comparing two engines with the "same" settings when their filter order or defaults differ.

Solution 
def softmax(z, T=1.0):
    z = np.asarray(z, dtype=np.float64) / T
    e = np.exp(z - z.max())
    return e / e.sum()

def top_p_filter(p, top_p):
    order = np.argsort(-p)                      # largest first
    csum = np.cumsum(p[order])
    keep_n = int(np.searchsorted(csum, top_p) + 1)   # first index where csum >= top_p, plus 1
    keep = order[:keep_n]
    q = np.zeros_like(p); q[keep] = p[keep]
    return q / q.sum()

Check: softmax(z) gives about [0.397, 0.218, 0.161, 0.108, 0.073, 0.029, 0.010, 0.004]. With top-p 0.8 the first four survive: the first three sum to 0.776, which is below 0.8, and adding the fourth gives 0.884.

Part B: test three temperatures

Predict first: at T = 0.3, about what share of 10,000 samples will be token 0? At T = 1? At T = 2?

from collections import Counter
for T in [0.3, 1.0, 2.0]:
    c = Counter(sample(z, T) for _ in range(10_000))
    p = softmax(z, T)
    ent = -(p * np.log(p)).sum()
    print(f"T={T}: token0 share={c[0]/1e4:.2f}  expected={p[0]:.2f}  entropy={ent:.2f} nats")

Entropy measures how spread out a distribution is. 0 means one certain choice. ln(8) ≈ 2.08 is the most spread possible for 8 tokens. Watch it rise with T.

Part C: a real model

Use the GPU runtime if you have it; the CPU works but is slower.

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
dev = "cuda" if torch.cuda.is_available() else "cpu"
model = AutoModelForCausalLM.from_pretrained(name, torch_dtype=torch.float16 if dev == "cuda" else torch.float32).to(dev)

msgs = [{"role": "user", "content": "Write one sentence about the ocean."}]
ids = tok.apply_chat_template(msgs, add_generation_prompt=True, return_tensors="pt").to(dev)

# 1. Look at the real next-token distribution
with torch.no_grad():
    logits = model(ids).logits[0, -1].float()
p = torch.softmax(logits, -1)
top = torch.topk(p, 10)
for prob, i in zip(top.values, top.indices):
    print(f"{prob.item():.3f}  {tok.decode(i)!r}")
print("vocab size:", logits.shape[0])

# 2. Generate with different settings
for kw in [dict(do_sample=False),
           dict(do_sample=True, temperature=0.7, top_p=0.9),
           dict(do_sample=True, temperature=1.5, top_p=1.0, top_k=0)]:
    for seed in [0, 1]:
        torch.manual_seed(seed)
        out = model.generate(ids, max_new_tokens=40, pad_token_id=tok.eos_token_id, **kw)
        print(kw, seed, "|", tok.decode(out[0, ids.shape[1]:], skip_special_tokens=True))

Part E: score text with logprobs

Sum of logprobs tells you how likely the model thinks a text is. Perplexity is e to the power of minus the mean logprob per token: lower means the text looks more "natural" to the model. Evaluation tools use it.

def perplexity(text):
    x = tok(text, return_tensors="pt").input_ids.to(dev)
    with torch.no_grad():
        lp = torch.log_softmax(model(x).logits[0, :-1].float(), -1)
    tok_lp = lp.gather(1, x[0, 1:, None]).squeeze(1)   # logprob of each actual next token
    return torch.exp(-tok_lp.mean()).item()

print(perplexity("The capital of France is Paris."))
print(perplexity("The capital of France is banana."))

Predict which is lower before you run it.

12. In the real world

How production systems use this
  • APIs: OpenAI-compatible servers (including vLLM and SGLang) accept temperature, top_p, max_tokens, stop, seed, n, logprobs, presence and frequency penalties. vLLM also accepts top_k, min_p and repetition_penalty.
  • Product defaults: extraction and classification use temperature 0 or near it. Chat often uses about 0.7 with top-p about 0.9. Many model cards publish their own recommended values; use them.
  • Evaluation: benchmarks that need repeatable scores use greedy decoding, or sample many times and report the average.
  • Confidence signals: logprobs of the chosen tokens give a cheap confidence score for classification and routing.

14. Summary

  • The model outputs one logit per vocabulary token. Softmax turns logits into probabilities; only differences between logits matter.
  • Greedy picks the top token. Sampling draws at random by probability. Beam search keeps several candidate sequences.
  • Temperature divides logits: low T sharpens, high T flattens, T = 0 means greedy.
  • Top-k keeps a fixed number of tokens; top-p keeps a fixed probability mass; min-p keeps tokens above a share of the top token's probability. Then renormalize.
  • Penalties, logit bias and stop rules give more control. Structured output masks tokens.
  • Temperature 0 is not always repeatable on servers, because kernel sums can depend on batch size.
