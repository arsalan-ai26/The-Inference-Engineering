Neural nets from first principles

A neural network is a stack of matmuls with simple bends between them, tuned by a loop that nudges every weight to reduce an error. This chapter builds that idea from one neuron up to the pieces every transformer uses: embeddings, normalization and residual connections. It ends with the reason older networks failed on long text, which is the problem attention solves.

Level: beginner Time: 4 to 5 hours with the lab Needs: 1.1 to 1.4 Compute: Colab CPU
Before you start: skip check
  1. Why does a network need an activation function between its matmuls?
  2. In one sentence, what does backpropagation compute?
  3. Why do transformers add the input of each block back to its output?
Answers
  1. Without it, a stack of matmuls equals one matmul, so extra layers add nothing.
  2. The gradient of the loss with respect to every weight, using the chain rule from the output back to the input.
  3. The residual connection gives gradients a direct path through deep stacks, and lets each block add a small change instead of rebuilding the whole vector.

1. One neuron

A neuron takes a vector of inputs, computes a dot product with its own weight vector, adds a bias, and applies a simple non-linear function:

output = activation( w · x + b )
Definitions

Weight (w): a learned number that says how much one input matters.

Bias (b): a learned number added after the dot product. It shifts the output.

Activation function: a fixed non-linear function applied to the result.

Parameters: all weights and biases together. "8B parameters" counts these.

A layer is many neurons that read the same input. Stack their weight vectors as columns and the whole layer is one matmul plus a bias vector: y = activation(x W + b). That is the linear layer from chapter 1.1, followed by an activation.

2. Why the bend matters

Matmuls compose. Applying W₁ and then W₂ is the same as applying the single matrix W₁W₂. So without an activation, a 100-layer network collapses into a 1-layer network. It can only draw straight lines (more exactly, flat planes) through the data.

An activation function breaks this. Each layer can now bend the space a little, and many bends together can fit almost any shape.

Modern LLMs use a gated MLP called SwiGLU: two parallel linear layers, one passed through SiLU, multiplied element by element, then a third linear layer. You read its code in chapter 1.4. It has three weight matrices instead of two, which is why Llama's MLP holds 3 × 4,096 × 14,336 parameters per layer.

3. Loss: a number that says how wrong

To improve a network, you need a single number that measures how bad its output is. This is the loss. Lower is better.

  • Mean squared error for numbers: the average of (prediction − target)².
  • Cross-entropy for choices among classes: −log(probability given to the correct class). If the model gives the right token probability 0.9, the loss is −ln(0.9) = 0.105. If it gives 0.01, the loss is 4.6.

LLMs are trained with cross-entropy on the next token, averaged over every position in the text. This is exactly the negative of the mean logprob from chapter 1.2, and perplexity is e raised to it. A pre-trained model is simply a network that got this loss low on trillions of tokens.

4. Gradients: which way is downhill

Picture the loss as a landscape. Each weight is one direction you can move in. The gradient of the loss with respect to a weight tells you two things: which direction increases the loss, and how steeply.

Definitions

Derivative: how much an output changes when you change one input by a tiny amount. If dL/dw = 3, increasing w by 0.001 increases L by about 0.003.

Gradient: the list of derivatives of the loss with respect to every parameter.

Gradient descent: move each weight a small step against its gradient: w ← w − (learning rate × dL/dw).

Learning rate: the step size. Too small: training is slow. Too large: the loss jumps around or explodes.

5. Backpropagation: the chain rule, run backwards

A network is a chain of simple steps. The chain rule says: the derivative of the whole chain is the product of the derivatives of each step. If L depends on ŷ, and ŷ depends on w, then dL/dw = dL/dŷ × dŷ/dw.

Backpropagation applies this from the loss backwards through every step. Each step needs only its own local derivative and the gradient that arrives from the step after it. One backward pass gives the gradient of every weight, for about twice the cost of the forward pass. That is why training a model costs about 3 times the FLOPs of running it (forward plus about 2× for backward).

Interactive: one gradient step on a two-weight network
Network: h = w₁ × x, a = ReLU(h), ŷ = w₂ × a, loss L = (ŷ − y)². Forward values are in indigo. Gradients flowing back are in amber. Press the buttons in order.

Worked example (the default numbers)

Forward: h = 0.5 × 2 = 1. a = ReLU(1) = 1. ŷ = 0.8 × 1 = 0.8. L = (0.8 − 3)² = 4.84.

Backward: dL/dŷ = 2(ŷ − y) = −4.4. dL/dw₂ = dL/dŷ × a = −4.4. dL/da = dL/dŷ × w₂ = −3.52. ReLU passes the gradient through because h > 0, so dL/dh = −3.52. dL/dw₁ = dL/dh × x = −7.04.

Update with learning rate 0.05: w₁ = 0.5 + 0.352 = 0.852. w₂ = 0.8 + 0.22 = 1.02. New loss = (1.02 × 1.704 − 3)² ≈ 1.59. The loss fell from 4.84.

This is why inference is its own engineering field. The weights never change, so you can compress them, compile the model for one GPU type, and reorganize memory for many users at once. Fine-tuning (Part 7) brings training back in a small, controlled form.

7. Embeddings: turning IDs into vectors

A network needs vectors, but text arrives as token IDs: integers such as 15496. An embedding table is a learned matrix of shape [vocabulary size, hidden size]. Row i is the vector for token i. Looking up a token is just reading one row; there is no multiplication.

During training, tokens used in similar contexts get similar rows, so their dot products are high. That is how "meaning" enters the network as geometry. The embedding table of Llama 3.1 8B is 128,256 × 4,096 = 525 M parameters, about 6.5% of the model. Chapter 2.1 covers this in depth.

8. Normalization: keeping numbers in range

As a vector passes through many layers, its values can grow or shrink a lot. Large swings make training unstable and push values out of the safe range of low-precision formats (chapter 1.3). A normalization layer rescales each token vector to a standard size.

  • LayerNorm: subtract the vector's mean, divide by its standard deviation, then multiply by a learned scale and add a learned shift. Used in GPT-2.
  • RMSNorm: divide by the root mean square of the vector (no mean subtraction, no shift), then multiply by a learned scale. Cheaper, and used by Llama, Qwen and most current LLMs.
RMSNorm(x) = x ÷ √(mean(x²) + ε) × g

ε is a tiny number (such as 10⁻⁶) that prevents division by zero. g is the learned scale, one value per element. The norm works on each token vector separately, along the hidden dimension. For inference, normalization is cheap in FLOPs but it reads and writes the whole activation, so engines fuse it into neighbouring kernels (chapter 5.4).

9. Residual connections: the main road

Deep networks used to be hard to train. Gradients pass back through every layer, and each layer multiplies them by its local derivative. Through 50 layers, a factor of 0.8 per layer leaves 0.8⁵⁰ ≈ 0.00001 of the signal. The early layers stop learning. This is the vanishing gradient problem.

A residual connection (also called a skip or shortcut connection) adds the block's input to its output:

x_next = x + Block(x)

The derivative of x with respect to itself is 1, so gradients always have a direct path back through the "+". Each block only has to learn a correction, not the whole vector.

A good mental model is the residual stream: a main road that runs from the embedding to the output. Each attention block and each MLP block reads from the road, computes something, and adds its result back onto the road. Every transformer layer has this structure:

The blocks read a normalized copy ("pre-norm"), but they add to the un-normalized stream. That detail matters when you read model code: there are two normalizations per layer, plus a final one before the output head.

10. Why older networks failed on long text

Before transformers, text models were mostly recurrent neural networks (RNNs and their improved form, LSTMs). An RNN reads one token at a time and keeps a fixed-size "memory" vector. At each step it mixes the new token into that vector.

This design has two problems that matter for this book:

  1. Information fades. Everything the model knows about token 1 must survive being squeezed through every later update. By token 1,000, early details are mostly gone. Gradients that would teach it to keep them also fade on the way back.
  2. No parallelism over the sequence. Step t needs the memory from step t − 1, so training cannot process the tokens of a text at the same time. GPUs, which want huge parallel matmuls, sit mostly idle.
Interactive: how much of token 1 survives?
A simple model of fading: each RNN step keeps a share r of the old signal. Attention looks back at every earlier token directly, so the distance does not matter.

Attention (chapter 2.2) fixes both: every token can read every earlier token directly through a dot product, and all positions are computed in parallel during training and prefill. The price is that the model must keep a record of every earlier token. That record is the KV cache (chapter 2.4), and managing it is much of what inference engineering is about. Some new architectures bring back fixed-size state to avoid that cost (chapter 2.7).

11. Expert layer

Why inference cares about training choices

Training decisions set inference costs. Pre-norm with RMSNorm keeps activations in a range that suits BF16. Gated MLPs add a third matrix. Weight tying (sharing the embedding and output head) saves memory. Grouped-query attention, chosen at training time, shrinks the KV cache. You inherit all of these when you serve a model.

Massive activations and outliers

Trained LLMs develop a few hidden dimensions with values hundreds of times larger than the rest, often tied to specific tokens such as the first token. Normalization keeps the network working, but these outliers break naive 8-bit and 4-bit activation quantization (chapter 4.1).

Autograd is a graph, not magic

PyTorch records each operation during the forward pass and stores what each local derivative needs (for example, the input of a ReLU). Backward replays the graph in reverse. A micrograd-style engine with about 100 lines of Python does the same thing for scalars. Building one, as in the lab, removes the mystery.

12. Common mistakes

  • Thinking more layers help without activations. Linear layers compose into one.
  • Thinking the gradient points downhill. It points uphill; descent moves against it.
  • Using inference FLOPs (2 × parameters) to estimate training cost. Training is about 6 × parameters per token.
  • Normalizing over the wrong dimension. LayerNorm and RMSNorm act on each token's hidden vector, not across the batch.
  • Forgetting that the residual stream is not normalized. The norm is applied to the copy a block reads.

13. Lab

Goal: do a gradient step by hand, build a tiny autograd engine, check both with PyTorch, then train a small network.

Part A: one step by hand

Use x = 1.5, y = 2, w₁ = −0.4, w₂ = 1.2 with the network of section 5. On paper (or in the widget), compute the loss, both gradients and the new weights with learning rate 0.1.

Hint

Look at h first. What does ReLU do to its gradient when its input is negative?

Answer

h = −0.6, a = 0, ŷ = 0, L = 4. dL/dŷ = −4, dL/dw₂ = −4 × 0 = 0. ReLU blocks the gradient (h < 0), so dL/dw₁ = 0. Nothing updates. This is a "dead ReLU": a neuron whose input is always negative never learns. Smooth activations such as GELU and SiLU avoid this.

Part B: check with PyTorch autograd

import torch
x, y = torch.tensor(2.0), torch.tensor(3.0)
w1 = torch.tensor(0.5, requires_grad=True)
w2 = torch.tensor(0.8, requires_grad=True)
loss = (w2 * torch.relu(w1 * x) - y) ** 2
loss.backward()
print(loss.item(), w1.grad.item(), w2.grad.item())   # 4.84, -7.04, -4.4

Change the numbers to your Part A values and confirm both gradients are 0.

Part C: a 40-line autograd engine

Read this code line by line. The AI can explain any line, but you should be able to say what _backward does for each operation.

class Value:
    def __init__(self, data, parents=(), op=""):
        self.data, self.grad = data, 0.0
        self._parents, self._op = parents, op
        self._backward = lambda: None
    def __add__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data + o.data, (self, o), "+")
        def bw(): self.grad += out.grad; o.grad += out.grad          # d(a+b)/da = 1
        out._backward = bw; return out
    def __mul__(self, o):
        o = o if isinstance(o, Value) else Value(o)
        out = Value(self.data * o.data, (self, o), "*")
        def bw(): self.grad += o.data * out.grad; o.grad += self.data * out.grad   # d(ab)/da = b
        out._backward = bw; return out
    def relu(self):
        out = Value(max(0.0, self.data), (self,), "relu")
        def bw(): self.grad += (out.data > 0) * out.grad
        out._backward = bw; return out
    def __pow__(self, k):
        out = Value(self.data ** k, (self,), f"**{k}")
        def bw(): self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = bw; return out
    def __sub__(self, o): return self + (o * -1 if isinstance(o, Value) else -o)
    def backward(self):
        order, seen = [], set()
        def build(v):                       # topological order: parents before children
            if v not in seen:
                seen.add(v); [build(p) for p in v._parents]; order.append(v)
        build(self); self.grad = 1.0
        for v in reversed(order): v._backward()

w1, w2 = Value(0.5), Value(0.8)
L = (w2 * (w1 * 2.0).relu() - 3.0) ** 2
L.backward()
print(L.data, w1.grad, w2.grad)            # must match Part B

Why does the code use += for gradients and not =? Try a = Value(3.0); b = a * a; b.backward() and check that a.grad is 6.

Part D: train a small network

Fit a curve with a 2-layer MLP. Predict first: with no activation, can it fit y = sin(x)?

import torch, torch.nn as nn, math
torch.manual_seed(0)
X = torch.linspace(-math.pi, math.pi, 256).unsqueeze(1)    # [256, 1]
Y = torch.sin(X)
for act in [nn.Identity(), nn.ReLU(), nn.SiLU()]:
    net = nn.Sequential(nn.Linear(1, 64), act, nn.Linear(64, 64), act, nn.Linear(64, 1))
    opt = torch.optim.Adam(net.parameters(), lr=1e-2)
    for step in range(2000):
        loss = ((net(X) - Y) ** 2).mean()
        opt.zero_grad(); loss.backward(); opt.step()
    print(f"{act.__class__.__name__:9s} final loss {loss.item():.5f}")

Identity stays stuck near 0.2, the error of the best straight line through a sine wave. ReLU and SiLU go close to zero (about 10⁻⁶).

Part E: see normalization and residuals work

def deep(n_layers, residual, norm):
    torch.manual_seed(0)
    layers = nn.ModuleList([nn.Linear(256, 256) for _ in range(n_layers)])
    x = torch.randn(32, 256, requires_grad=True)
    h = x
    for lin in layers:
        z = torch.tanh(lin(nn.functional.rms_norm(h, (256,)) if norm else h))
        h = h + z if residual else z
    h.pow(2).mean().backward()
    return h.abs().mean().item(), layers[0].weight.grad.abs().mean().item()

for res in [False, True]:
    for norm in [False, True]:
        act, g = deep(50, res, norm)
        print(f"residual={res!s:5} norm={norm!s:5}  |activation|={act:8.3f}  |grad of layer 0|={g:.2e}")

Look at the gradient reaching layer 0 of a 50-layer stack. Which combination keeps it largest? Which keeps the activations in a stable range?

What you should see

With no residual and no norm, the gradient at layer 0 is around 10⁻¹⁷: it has vanished. Adding RMSNorm alone brings it to about 10⁻³. The residual connection alone gives the largest gradient (about 0.05), but the activations grow as each layer adds to the stream. Residual plus norm keeps a healthy gradient (about 0.01) with activations that grow more slowly. Real transformers use both, plus careful weight initialization. Exact values depend on the PyTorch version.

14. In the real world

Where this shows up in serving
  • Every decoder layer of Llama, Qwen, Mistral and DeepSeek is "RMSNorm, attention, add, RMSNorm, MLP, add". Inference engines implement exactly these steps, often fused into fewer kernels.
  • Training cost estimates use 6 × parameters × training tokens. Inference estimates use 2 × parameters per token.
  • Fine-tuning (Part 7) uses backpropagation, but often updates only small added matrices (LoRA) to save memory.
  • Numerical issues in production (NaNs, quality drops after quantization) often trace back to normalization, outlier activations or overflow in the residual stream.

16. Summary

  • A layer is a matmul plus a bias, followed by a non-linear activation. Without activations, layers collapse into one.
  • Loss measures error; LLMs use cross-entropy on the next token.
  • Backpropagation uses the chain rule to get every weight's gradient; gradient descent steps against it.
  • Training costs about 6 × parameters FLOPs per token; inference about 2 ×.
  • Embeddings turn token IDs into vectors; RMSNorm keeps vectors in range; residual connections keep gradients alive.
  • RNNs squeeze history into a fixed state, so they forget and cannot parallelize. Attention keeps every token, at the cost of the KV cache.
