Attention and the transformer block

Attention lets every token look at every earlier token and pull in the information it needs. It is the one idea that separates transformers from older networks, and it is the part of the model whose cost grows with context. This chapter builds attention from a dot product up to a full transformer block, with every shape and every FLOP counted.

Before you start: skip check
  1. Write the attention formula and say what each part does.
  2. Why divide the scores by √d?
  3. For a 2,048-token prompt, 32 heads and head size 128, how big is one layer's full score matrix in BF16?
Answers
  1. softmax(QKᵀ / √d + mask) V. QKᵀ scores every query against every key; the mask hides future tokens; softmax turns each row of scores into weights; multiplying by V takes the weighted average of value vectors.
  2. A dot product of two length-d vectors with unit-variance elements has variance d. Dividing by √d keeps scores near unit size, so softmax does not saturate into a hard one-hot choice.
  3. 32 × 2,048 × 2,048 × 2 bytes ≈ 268 MB per layer (per sequence). This is why fused kernels never store it.

1. The problem: each word needs its context

After the embedding step (chapter 2.1), each token has a vector that does not depend on its neighbours. But meaning does. In "I wrote a book because I thought it would be easy", the vector for "it" must somehow learn that "it" means the book, not "I".

Chapter 1.5 showed why recurrent networks struggle: they squeeze everything into one state that fades. Attention takes a different route. For each token, it looks at every earlier token directly, decides how relevant each one is, and mixes their information in, weighted by relevance. Distance does not matter.

2. Queries, keys and values

A helpful analogy is a library search. You have a question (the query). Every book has a label on its spine (the key) and content inside (the value). You compare your question with every label, and read more from the books whose labels match best.

Attention does this with vectors. Each token's vector x is multiplied by three learned weight matrices:

q = x W_Q k = x W_K v = x W_V
Definitions

Query (q): what this token is looking for.

Key (k): what this token offers to be found by. Compared with queries.

Value (v): the information this token passes on when another token attends to it.

Attention weight: how much one token reads from another. The weights for one query add up to 1.

The same three matrices are used for every token. That is why attention works for any sequence length: the weights do not depend on how many tokens there are.

3. The formula, one step at a time

For a sequence of T tokens, stack the vectors into matrices Q, K and V, each of shape [T, d]. Then:

Attention(Q, K, V) = softmax( Q Kᵀ / √d + mask ) V
  1. Score. Q Kᵀ has shape [T, T]. Entry (i, j) is the dot product of query i with key j: how well token j matches what token i is looking for (chapter 1.1).
  2. Scale. Divide by √d. Without this, large d makes scores large, and softmax becomes almost one-hot: a single token takes all the weight and gradients vanish.
  3. Mask. Add −∞ to every entry where j > i. After softmax these become 0, so a token cannot see the future (section 5).
  4. Normalize. Softmax each row (chapter 1.2). Row i now holds token i's attention weights, adding up to 1.
  5. Mix. Multiply by V. Row i of the result is a weighted average of all value vectors, weighted by row i's attention weights. Shape [T, d].

Worked example: 3 tokens, d = 2

Queries and keys (one row per token): Q = [[1, 0], [0, 1], [1, 1]], K = [[1, 0], [0, 2], [1, 1]]. Values V = [[10, 0], [0, 10], [5, 5]].

Look at token 3 (the last query, [1, 1]). Its dot products with the three keys: 1, 2 and 2. Divide by √2: 0.71, 1.41, 1.41. Softmax: [0.20, 0.40, 0.40].

Output for token 3: 0.20 × [10, 0] + 0.40 × [0, 10] + 0.40 × [5, 5] = [4, 6]. Token 3 now carries a mix of the information from all three tokens, weighted towards tokens 2 and 3.

Token 1 can see only itself because of the mask, so its weights are [1, 0, 0] and its output is V's first row, [10, 0].

4. Multi-head attention

One attention operation produces one set of weights per token. But a token may need several kinds of information at once: which noun "it" refers to, what the verb tense is, what came just before. So the model runs several attention operations in parallel, called heads, each with its own smaller Q, K and V.

  1. Project x (size D) to Q, K and V, each of size D.
  2. Split each into H heads of size d = D / H. For Llama 3.1 8B: 32 heads of 128.
  3. Run attention separately in each head.
  4. Join (concatenate) the head outputs back into size D.
  5. Multiply by an output matrix W_O of shape [D, D] to mix information across heads.

In code, step 2 is the view and transpose pattern from chapter 1.4. Shapes for a batch: x [B, T, D] → Q [B, H, T, d] → scores [B, H, T, T] → output [B, H, T, d] → [B, T, D].

Multi-head attention costs the same FLOPs as one big head of size D for the projections; only the score step changes shape. Trained heads do specialize: some track the previous token, some track matching brackets or quotes, some follow references back to a name.

Many recent models use fewer key and value heads than query heads. This is grouped-query attention (GQA): several query heads share one key head and one value head. It does not change the attention math for each query head, but it makes K and V much smaller. That matters enormously for the KV cache, so chapter 2.4 covers it in detail.

5. The causal mask, and self vs cross attention

A language model is trained to predict the next token. If token i could see token i + 1, the task would be trivial and the model would learn nothing useful. The causal mask blocks every position j > i. Its pattern is a lower triangle.

The mask has a second, very important effect for inference: the output at position i depends only on tokens 1 to i. Adding tokens at the end never changes earlier positions' keys and values. Chapter 2.4 builds the KV cache on this fact.

6. The transformer block

A transformer block wraps attention with the pieces from chapter 1.5. Modern LLMs use the pre-norm order:

h = x + Attention( RMSNorm(x) ) out = h + MLP( RMSNorm(h) )
  • Attention moves information between tokens.
  • The MLP (also called the feed-forward network, FFN) works on each token separately. It holds most of the parameters and is often described as where the model stores facts.
  • Residual adds keep a main road through the network; norms keep values in range.

The whole model is: embedding lookup → N identical blocks → final norm → output head (chapter 1.2). Llama 3.1 8B has 32 blocks; Llama 3.1 70B has 80. The forward-pass tracer in chapter 1.4 walks one block line by line with real shapes.

7. What attention costs

A block has two kinds of work with very different scaling.

  1. Projections and MLP (all the matmuls with weight matrices). FLOPs = 2 × tokens × parameters. Linear in T.
  2. The attention core (QKᵀ and the multiply by V). Per layer, QKᵀ costs 2 × T × T × d per head, and the multiply by V costs the same. Over H heads with H × d = D, that is about 4 × T² × D FLOPs. Quadratic in T. A causal mask means only about half of the entries are needed, and good kernels skip the masked half.

For short prompts the matmuls dominate. For long prompts, the T² term takes over. There is also a memory problem: the full score matrix is [H, T, T] per layer. Writing it to GPU memory and reading it back is slow, and at long context it does not fit at all.

Interactive: where the prefill FLOPs go
One prefill of T tokens through the whole model. Linear FLOPs = 2 × T × (non-embedding parameters). Attention-core FLOPs = 4 × T² × (heads × head size) × layers, halved for the causal mask.
Watch out: "the KV cache makes attention linear"

You may read that the KV cache turns attention from quadratic to linear. That is only half true. With a cache, each decode step costs attention work linear in the current context, because one new query reads all cached keys. But a full generation of N tokens still does about N²/2 key reads in total, and prefill of a T-token prompt is still quadratic in T. What the cache removes is the recomputation of old keys and values (chapter 2.4).

8. How real kernels compute attention

Inference engines never build the full [T, T] score matrix in GPU memory. They use fused attention kernels such as FlashAttention, which do the whole formula in one pass:

  1. Split Q, K and V into small tiles that fit in fast on-chip memory.
  2. For each tile of queries, loop over tiles of keys and values.
  3. Compute that block of scores, apply the mask, and update a running softmax: keep the running maximum and running sum for each row, and rescale the partial output when a new maximum appears (the "online softmax").
  4. Write only the final output [T, d] back to memory.

The FLOPs are the same, or slightly more. What changes is memory traffic: the T × T matrix never leaves the chip. The result is exact, not an approximation, and much faster. In PyTorch, F.scaled_dot_product_attention picks such a kernel when one is available. Chapter 4.2 goes inside these kernels.

9. Expert layer

Attention sinks

Trained models often put a large share of attention weight on the very first token, whatever it is. Softmax weights must add up to 1, so heads that "do not need anything" park their weight there. This matters for long-context tricks: if you drop the first tokens to save memory, quality collapses. Keeping a few "sink" tokens, as StreamingLLM does, avoids this. Some newer models add a learned sink value per head.

Sliding-window and local attention

Some models limit each token to the last W tokens (for example W = 4,096). The attention core then costs T × W instead of T², and the cache stops growing. Many models mix window layers with full-attention layers to keep long-range ability (chapter 2.4, expert layer).

Softmax in low precision

Scores can be large. Kernels subtract the row maximum before exponentiation (chapter 1.2) and keep the running sums in FP32 even when Q, K and V are BF16 or FP8. FP8 attention is possible on Hopper and Blackwell GPUs, but needs careful scaling.

Interpretability view

Research on trained transformers finds "induction heads": pairs of heads that find an earlier occurrence of the current token and copy what came after it. They are a key mechanism behind in-context learning. This is why the attention pattern, not just the weights, encodes much of what a model does with a prompt.

10. Common mistakes

  • Applying softmax over the wrong dimension. Each query row must sum to 1 (dim = −1 on [.., T_q, T_k]).
  • Forgetting the √d scale or the causal mask when writing attention by hand.
  • Thinking attention parameters grow with context. W_Q, W_K, W_V and W_O have fixed shapes; only the work grows.
  • Counting attention FLOPs for both triangles under a causal mask. Efficient kernels skip the masked half.
  • Assuming the score matrix is stored in memory during inference. Fused kernels never store it.

Part D: a real model's attention

from transformers import AutoModelForCausalLM, AutoTokenizer
tok = AutoTokenizer.from_pretrained("openai-community/gpt2")
m = AutoModelForCausalLM.from_pretrained("openai-community/gpt2", attn_implementation="eager").eval()
text = "The animal did not cross the street because it was too tired"
ids = tok(text, return_tensors="pt").input_ids
with torch.inference_mode():
    att = m(ids, output_attentions=True).attentions     # tuple: one [1, H, T, T] per layer
toks = tok.convert_ids_to_tokens(ids[0])
print(len(att), att[0].shape)
it = toks.index("Ġit")
for layer in [2, 5, 9]:
    w = att[layer][0, :, it].mean(0)                   # average over heads
    top = w.topk(3)
    print(layer, [(toks[i], round(p.item(), 2)) for p, i in zip(top.values, top.indices)])

Part E: measure the quadratic cost (T4)

import time
F = torch.nn.functional
dev = "cuda"
def bench(T, fused, H=16, d=64, reps=10):
    q, k, v = (torch.randn(1, H, T, d, device=dev, dtype=torch.float16) for _ in range(3))
    f = (lambda: F.scaled_dot_product_attention(q, k, v, is_causal=True)) if fused else (lambda: attention(q, k, v)[0])
    f(); torch.cuda.synchronize(); torch.cuda.reset_peak_memory_stats()
    t = time.perf_counter()
    for _ in range(reps): f()
    torch.cuda.synchronize()
    return (time.perf_counter() - t) / reps * 1e3, torch.cuda.max_memory_allocated() / 1e6

for T in [512, 1024, 2048, 4096, 8192]:
    ms_f, mb_f = bench(T, True)
    try: ms_n, mb_n = bench(T, False)
    except torch.OutOfMemoryError: ms_n, mb_n = float("nan"), float("nan")
    print(f"T={T:5d}  fused {ms_f:7.2f} ms {mb_f:7.0f} MB   naive {ms_n:7.2f} ms {mb_n:7.0f} MB")

Predict first: when T doubles, by what factor should time grow? By what factor does the naive version's memory grow?

What you should see

The fused kernel's time grows close to 4 times per doubling at large T (the T² term), and its memory stays small. The naive version's memory grows about 4 times per doubling, because it stores the full [H, T, T] score matrix, and at some T it runs out of memory on a 16 GB T4.

12. In the real world

Attention in production systems
  • Every serving engine uses fused attention kernels (FlashAttention, FlashInfer, or vendor kernels in TensorRT-LLM). They choose different kernels for prefill (many queries) and decode (one query per sequence).
  • Long-context products (100K to 1M tokens) are limited mostly by attention: quadratic prefill time and the memory for keys and values.
  • Model design trades attention cost against quality: grouped-query attention, multi-head latent attention, sliding windows and hybrid layers are all ways to make attention cheaper to serve.
  • Multimodal models run the same attention over image or audio tokens, so a single image can add hundreds to thousands of tokens to the sequence.

14. Summary

  • Attention = softmax(QKᵀ/√d + mask) V. Each token mixes value vectors from earlier tokens, weighted by query-key match.
  • Q, K and V come from three learned projections; heads split the work into H parallel attentions of size d = D/H, joined by W_O.
  • The causal mask makes position i depend only on tokens 1 to i. This is what makes caching possible.
  • A block is: x + Attention(Norm(x)), then + MLP(Norm(·)). Attention moves information between tokens; the MLP works per token.
  • Projections cost 2 × T × parameters; the attention core costs about 4 × T² × D per layer (half with causal skipping).
  • Fused kernels compute attention exactly without storing the T × T matrix.
