Math for papers IV: tail latency, confidence, queues and algorithm analysis

Systems papers (Orca, vLLM, Sarathi-Serve, DistServe, Mooncake, Aegaeon, DeepSeek's kernel reports) argue with a different kind of math: latency percentiles and goodput, how sure a measurement is, how queues behave as load rises, how the cost of an algorithm grows, and how a sequential recurrence can run in parallel. This optional chapter covers each with a short derivation and a simulation, so a reader can check a paper's claims instead of taking them on trust.

Level: optional, for reading papers Time: 3 hours with the lab Needs: 1.7 Compute: CPU, seconds
Before you start: skip check
  1. A server is 90% utilized with random arrivals. Roughly how does its average latency compare with the same server at 50%?
  2. An evaluation of 500 items reports 80% accuracy. About how wide is its 95% interval?
  3. How can a recurrence ht = atht−1 + bt over 1,024 steps run in about 10 parallel steps?
Answers
  1. About 5 times higher in the simplest queue model (latency ∝ 1 ÷ (1 − utilization): 10 against 2), and the tail grows the same way.
  2. About ±3.5 points: 1.96 × √(0.8 × 0.2 ÷ 500).
  3. The step "apply (a, b)" composes associatively, so pairs can be combined in a tree: log₂ 1,024 = 10 levels (a parallel scan).

2. Percentiles and the tail

Definitions

Percentile: the p-th percentile (p50, p95, p99) is the value below which p% of measurements fall. p50 is the median.

Tail latency: the high percentiles, which describe the slowest requests rather than the typical one.

Goodput: the rate of requests that meet their latency targets (SLOs), as opposed to total throughput.

Latency distributions are skewed: most requests are fast, a few are much slower (a long prefill landed in their batch, a cache miss, a preemption). The mean is pulled by the tail while the median ignores it, which is why papers report p50 and p99 separately (lab Part A: with 2% slow requests the mean is 0.37 s, p50 0.30 s, p99 3.1 s). The tail matters more as systems fan out: if a page or an agent step waits for n parallel calls and each is slow 1% of the time, the step is slow 1 − 0.99n of the time, 63% at n = 100. An agent that makes many model calls lives in the tail.

3. How sure is a measurement?

An accuracy measured on N independent items is an average of 0s and 1s, so (chapter 1.7) its standard error is √(p(1 − p) ÷ N), and a 95% confidence interval is about ±1.96 standard errors. At 80% accuracy that is ±7.8 points for 100 items, ±3.5 for 500 and ±1.8 for 2,000 (lab Part B). Two practical tools follow:

  • The bootstrap. Resample the N results with replacement thousands of times and take the 2.5th and 97.5th percentiles of the recomputed metric. It works for any metric (a median latency, a pass@k) without a formula, and agrees with the formula where one exists.
  • Paired comparison. When two models are scored on the same items, analyze the per-item difference. Items that both get right or both get wrong cancel, so the standard error of the difference is smaller than treating the two scores as independent (lab Part B: 0.023 against 0.027). Chapter 7.6 uses this to detect small regressions with fewer items.

Latency benchmarks need the same care: repeat runs, report the spread, and do not call a 3% difference real when run-to-run variation is 5% (chapter 6.1).

4. Queues: Little's law and the utilization curve

Definitions

Little's law: in any stable system, the average number of requests inside (L) equals the arrival rate (λ) times the average time each spends inside (W): L = λW. It needs no assumption about distributions.

Utilization: ρ = λ ÷ μ, arrival rate over service capacity.

M/M/1 queue: the simplest queue model: random (Poisson) arrivals, random (exponential) service times, one server. Its average time in the system is W = 1 ÷ (μ − λ).

Little's law is why autoscaling on concurrency works (chapter 6.3): at 20 requests per second and 5 seconds per request, 100 requests are in flight, whatever the distributions. The M/M/1 formula, rewritten as W = (1/μ) ÷ (1 − ρ), shows the knee: latency is twice the bare service time at 50% utilization, 5 times at 80%, 10 times at 90% and 20 times at 95%, and the p99 grows the same way (lab Part C simulates it). An inference server is not an M/M/1 queue (it batches, so its service rate rises with load until memory runs out), but the shape holds near saturation, which is why capacity plans keep headroom (chapter 6.5) and why goodput falls off a cliff past a certain request rate in serving papers.

5. Algorithm cost: big-O and expected bounds

Big-O describes how cost grows with input size, ignoring constant factors: attention prefill is O(T²) in the context length, DSA's core attention O(T × k) (chapter 4.2). Papers with randomized algorithms state expected costs, and the same small toolkit keeps appearing: linearity of expectation, and the harmonic number Hn = 1 + ½ + … + 1/n ≈ ln n + 0.577.

The classic example is the one inside DeepSelect's analysis (chapter 5.8): scan n values in random order and count how often a new maximum appears. Element i is a new maximum exactly when it is the largest of the first i, which happens with probability 1/i, so by linearity the expected count is Hn: about 14 for a million values. That is why a running threshold, raised only when something beats it, does almost no extra work, and why DeepSelect processes blocks in random order. Lab Part D checks the count by simulation.

6. Associative scans: recurrences in parallel

A linear recurrence ht = at ht−1 + bt looks inherently sequential. Treat each step as a pair (at, bt) meaning "multiply by a, then add b". Applying (a₁, b₁) then (a₂, b₂) is the same as applying (a₁a₂, a₂b₁ + b₂). That combine is associative, so pairs can be combined in any grouping, as a tree: T steps finish in log₂ T parallel levels. This parallel scan is how Mamba and linear attention train and prefill fast (chapter 2.7), and the same idea, with "merge two softmax partial results" as the combine, lets FlashAttention, Flash-Decoding and context parallelism split attention across blocks and GPUs (chapter 4.2). Lab Part E: 1,024 steps in 10 levels, matching the sequential loop to 10−15.

7. Expert layer

Open-loop and closed-loop load

A closed-loop benchmark (a fixed number of clients that send a new request when the previous one finishes) can never overload a server: when it slows, the arrival rate drops. Real traffic is open-loop (arrivals do not wait), so queues and tail latency grow as in section 4. Systems papers that measure capacity use open-loop arrivals at increasing rates; chapter 6.1 shows how.

Multiple comparisons

Comparing 20 configurations at a 95% level, about one will look significantly better by chance. When a paper or your own sweep reports the best of many settings, rerun the winner on fresh data before believing the gain.

8. Common mistakes

  • Reporting mean latency only, or a p99 from a few hundred requests (the p99 of 200 samples rests on 2 of them).
  • Calling a difference smaller than its confidence interval an improvement.
  • Benchmarking closed-loop and claiming a capacity.
  • Planning capacity at 95% utilization.
  • Assuming a recurrence must run step by step without checking whether its update is associative.

import numpy as np
rng = np.random.default_rng(0)
# Part A: latency distributions. Mean and median hide the tail
lat = np.concatenate([rng.lognormal(np.log(0.3), 0.3, 9_800), rng.lognormal(np.log(3.0), 0.4, 200)])  # 2% slow requests
print(f"A  mean {lat.mean():.2f} s, p50 {np.percentile(lat,50):.2f} s, p95 {np.percentile(lat,95):.2f} s, p99 {np.percentile(lat,99):.2f} s")
# fan-out: a page waits for n calls; if each is slow 1% of the time, how often is the page slow?
for n in (1, 10, 50, 100):
    print(f"   {n:3d} parallel calls, each slow 1% of the time: {1 - 0.99 ** n:.1%} of pages are slow")

# Part B: uncertainty of an accuracy measured on N items (chapter 7.6)
for N in (100, 500, 2000):
    acc = 0.80; se = np.sqrt(acc * (1 - acc) / N)
    items = rng.random(N) < acc
    boot = [rng.choice(items, N).mean() for _ in range(2000)]
    print(f"B  N={N:5d}: 95% interval ±{1.96*se:.3f} (formula), bootstrap [{np.percentile(boot,2.5):.3f}, {np.percentile(boot,97.5):.3f}] around {items.mean():.3f}")
# paired comparison: two models on the same 500 items, model B better by 2 points
N = 500; skill = rng.random(N)
a = rng.random(N) < np.clip(skill + 0.30, 0, 1); b = rng.random(N) < np.clip(skill + 0.32, 0, 1)
diff = b.astype(float) - a
se_paired = diff.std(ddof=1) / np.sqrt(N); se_unpaired = np.sqrt(a.var(ddof=1)/N + b.var(ddof=1)/N)
print(f"   difference {diff.mean():+.3f}: paired std error {se_paired:.3f}, unpaired {se_unpaired:.3f}")

# Part C: Little's law L = lambda * W, checked on a simulated queue, and the M/M/1 latency curve
def mm1(lam, mu, n=200_000):
    arr = np.cumsum(rng.exponential(1 / lam, n)); svc = rng.exponential(1 / mu, n)
    start = np.empty(n); end = np.empty(n); t = 0.0
    for i in range(n):
        start[i] = max(arr[i], t); t = end[i] = start[i] + svc[i]
    W = end - arr
    T = end[-1] - arr[0]; L = W.sum() / T                       # time-average number in system
    return W, L, lam * W.mean()
mu = 10.0                                                       # 10 requests per second of capacity
for rho in (0.5, 0.8, 0.9, 0.95):
    W, L, lw = mm1(rho * mu, mu)
    print(f"C  utilization {rho:.2f}: mean latency {W.mean():.3f} s (theory 1/(mu-lambda) = {1/(mu - rho*mu):.3f}), p99 {np.percentile(W,99):.2f} s, L {L:.2f} vs lambda*W {lw:.2f}")

# Part D: expected cost with harmonic numbers: how often does the running maximum change in a random order?
for n, trials in ((100, 500), (10_000, 200), (1_000_000, 20)):
    ch = [(lambda x: (x == np.maximum.accumulate(x)).sum())(rng.permutation(n)) for _ in range(trials)]
    print(f"D  n={n:>9,}: new maximum seen {np.mean(ch):.1f} times on average over {trials} orders; H_n = ln n + 0.577 = {np.log(n) + 0.5772:.1f}")

# Part E: a linear recurrence h_t = a_t * h_{t-1} + b_t computed sequentially and by a parallel (associative) scan
T = 1024; a = rng.uniform(0.9, 1.0, T); b = rng.standard_normal(T)
h = np.empty(T); acc = 0.0
for t in range(T): acc = a[t] * acc + b[t]; h[t] = acc
A, B = a.copy(), b.copy(); step = 1; levels = 0           # combine (a1,b1) then (a2,b2) -> (a1*a2, a2*b1 + b2)
while step < T:
    A2, B2 = A.copy(), B.copy()
    A2[step:] = A[step:] * A[:-step]; B2[step:] = A[step:] * B[:-step] + B[step:]
    A, B = A2, B2; step *= 2; levels += 1
print(f"E  {T} steps: parallel scan matches sequential (max diff {np.abs(B - h).max():.1e}) in {levels} parallel levels instead of {T} serial steps")

10. In the real world

Where this shows up
  • SLOs are written as percentiles (p95 TTFT, p99 TPOT), and goodput is the metric disaggregation papers optimize.
  • Evaluation harnesses report standard errors or bootstrap intervals next to scores.
  • Autoscalers use concurrency targets that are Little's law in practice.
  • Kernels for state-space models, top-k and softmax merges are parallel scans and reductions underneath.

12. Summary

  • Report percentiles; tails dominate fan-out systems and agents; goodput counts only requests within SLO.
  • Standard error √(p(1−p)/N); bootstrap for any metric; paired differences for model comparisons.
  • L = λW always; latency grows like 1/(1 − ρ) near saturation, so keep headroom.
  • Expected-cost arguments use linearity and harmonic numbers; random orders make bounds hold for every input.
  • Associative updates run as parallel scans in log T levels: state-space models, linear attention, attention merges.
