Guide

Glossary

Every term this book defines, in one place. Each entry links to the chapter that explains it with examples. Use the search box to filter.

A

Ablation
removing or changing one component to measure its contribution. Chapter 8.5
Acceptance length
the average number of tokens produced per target pass. Chapter 4.3
Acceptance rate α
the probability that a draft token is accepted. Chapter 4.3
Activation function
a fixed non-linear function applied to the result. Chapter 1.5
Active parameters
the weights one token actually uses: attention, embeddings and output head, shared experts, and k routed experts per layer. Sets FLOPs per token. Chapter 2.6
Active parameters vs total parameters
See the two entries in chapter 2.6. Active sets FLOPs per token; total sets memory. Chapter 2.6
Adam
keep running averages of g (first moment) and of g² (second moment, per element) and step by η × m̂ ÷ (√v̂ + ε), with bias corrections m̂, v̂ for the first steps. Each parameter gets its own effective step size. Chapter 1.9
Advantage
how much better an answer's reward is than expected; training raises the probability of tokens in answers with positive advantage and lowers it for negative ones. Chapter 7.4
Agent
a program that uses a model to choose actions (tool calls) step by step until a task is done. Chapter 6.8
All-gather
every GPU ends with all pieces. Chapter 4.5
All-reduce
every GPU contributes a tensor and every GPU ends with the sum. Chapter 4.5
All-to-all
every GPU sends a different piece to every other GPU. Chapter 4.5
Alpha (α)
a scaling factor for the update; the effective scale is α ÷ r. Chapter 7.3
Arithmetic intensity
(of an operation): its FLOPs ÷ the bytes it must read and write. Chapter 2.5
Attention-FFN disaggregation (AFD)
Running attention and the feed-forward or MoE layers of the same model on separate GPU pools, passing activations between them each layer (Step-3, MegaScale-Infer). Chapter 4.5
Attention sink
The first few tokens of a sequence, which receive large attention weights regardless of content. Keeping them makes sliding-window attention stable. Chapter 4.2
Attention weight
how much one token reads from another. The weights for one query add up to 1. Chapter 2.2
AWQ (activation-aware weight quantization)
A weight-only quantization method that scales up the small share of weight channels that see large activations before rounding, protecting the weights that matter most. Chapter 4.1

B

Batched matmul
a matmul on the last two dimensions, done independently for every index of the dimensions in front. Chapter 1.1
Batch-invariant
a request's result does not depend on the batch size or on the other requests in the batch. Not true for standard kernels. Chapter 6.6
BF16 (bfloat16)
A 16-bit float with FP32's 8 exponent bits and 7 mantissa bits: same range as FP32, less precision. The default weight format for serving. Chapter 1.3
Bias
a fixed number subtracted from the stored exponent so that negative powers are possible. For an exponent with E bits, the bias is 2^(E−1) − 1. Chapter 1.3
Bias (b)
a learned number added after the dot product. It shifts the output. Chapter 1.5
Block
storage for the keys and values of B consecutive tokens (B is the block size, commonly 16 in vLLM), for the layers that share a block layout. Chapter 3.3
Block table
one list per request. Entry i is the physical block that holds the request's tokens i × B to (i + 1) × B − 1. Chapter 3.3
Blue-green deployment
Running a full second fleet with the new version and switching all traffic at once. Chapter 6.5
BPE (byte-pair encoding)
A tokenizer training method that starts from bytes or characters and repeatedly merges the most frequent adjacent pair into a new token. Chapter 2.1

C

Cache-aware routing
Sending a request to the replica most likely to hold its prefix in the KV cache, balanced against that replica's load. Chapter 4.4
Cache salt
A per-tenant value mixed into prefix-cache block hashes so only requests with the same salt can share cached KV blocks. Chapter 6.9
Canary deployment
Sending a small share of traffic to a new version, watching its metrics, and raising the share in steps or rolling back. Chapter 6.5
Cascade attention (shared-prefix attention)
Computing attention over a prefix shared by many sequences once per decode step, with all their queries in one matrix product, then merging with per-sequence suffix attention (Hydragen). Chapter 4.4
Catastrophic forgetting
Loss of skills that are not in the fine-tuning data, such as general instruction following, after training on a narrow task. Chapter 7.2
Causal encoder-decoder (CED)
V4.1-Flash's layout of its 40 layers into a 20-layer causal encoder and a 20-layer decoder, where the decoder layers' global KV is projected from the last encoder layer's hidden state instead of each layer's own. Prefill needs only the encoder, so it activates 8B parameters per token against 16B in decode. Chapter 4.8
Causal mask
A mask that stops each token attending to later tokens, so a token's output depends only on itself and earlier tokens. Chapter 2.2
Chat template
the rule (a Jinja template stored with the tokenizer) that turns a list of messages into the exact token sequence the model was trained on, with its special tokens. Chapter 7.2
Chunked prefill
Splitting a long prompt's prefill into chunks that run in the same steps as other requests' decodes, so long prompts do not stall token output for everyone. Chapter 3.2
Cold start
The time from deciding to add a replica to it serving traffic: getting a machine, pulling the image, loading weights, compiling and warming up. Chapter 6.2
Collective
a communication pattern among a group of GPUs. Chapter 4.5
Colocated (aggregated) serving
prefill and decode run on the same engine and GPUs. Chapter 4.6
Compressed Sparse Attention 2 (CSA2)
V4.1's attention, in which layers share global KV and top-k selections. Each layer is statically Full (computes its own KV and selection), Reindex (reuses an earlier layer's KV but selects again) or Reuse (reuses both). Chapter 4.8
Compressed Sparse Attention (CSA)
DeepSeek-V4's attention that first compresses the KV of every m tokens into one entry (m = 4 in both V4 models, using learned weights over overlapping windows), then applies DSA so each query attends to only the top-k compressed entries (512 in V4-Flash, 1,024 in V4-Pro). Chapter 4.8
Compute-bound
the math units are the bottleneck. Time ≈ FLOPs ÷ achievable FLOP/s. Faster math (more tensor cores, lower precision) helps; nothing else does. Chapter 5.1
Compute capability
a version number for the GPU's architecture. T4 is 7.5, A100 8.0, L4 8.9, H100 9.0, B200 10.0. Software must include code compiled for your GPU's capability. Chapter 1.6
Concurrency target
The number of simultaneous requests one replica should handle while meeting the SLO. Autoscalers scale on it. Chapter 6.3
Confidence-scheduled verification
Choosing per request how many draft tokens to verify from their predicted acceptance probabilities and the engine's cost curve, instead of a fixed draft length. Chapter 4.3
Confidential VM
a virtual machine whose memory is encrypted with keys held inside the CPU, so the host operating system and hypervisor cannot read it (Intel TDX, AMD SEV-SNP). Chapter 6.7
Constrained decoding (structured output)
Masking the logits at each step so only tokens that keep the output valid for a grammar or JSON schema can be sampled. Chapter 3.5
Container
a running instance of an image with a thin writable layer that disappears when it stops. Chapter 6.2
Context
all tokens the model can see at a step. This is the prompt plus all tokens made so far. Chapter 2.4
Context engineering
Designing what goes into a model's context, and in what order, for quality, latency and cache reuse. Chapter 6.8
Context parallelism
Splitting one long sequence across GPUs so each holds part of its tokens and KV cache. Chapter 4.5
Continuous batching
Scheduling at the level of single token steps: finished requests leave and new ones join the running batch at every step, instead of waiting for a whole batch to finish. Chapter 3.2
Conversational dataset
each example is a list of messages with roles (system, user, assistant, sometimes tool). Chapter 7.2
Cross-entropy
CE(p, q) = −Σ p(x) log q(x), the average surprise when outcomes come from p but you predict with q. A language model's training loss is the cross-entropy between the text and the model. Chapter 1.7
CUDA event
a marker recorded in a stream; the time between two events is GPU time, measured on the GPU. Chapter 5.3
CUDA graph
A recorded sequence of GPU kernel launches that can be replayed with one call, removing per-kernel CPU launch overhead in decode. Chapter 3.4
CUDA runtime
the libraries that programs call to run work on the GPU. PyTorch wheels bundle their own copy, so you do not need to install CUDA separately to use PyTorch. Chapter 1.6
CUDA toolkit
the compiler (nvcc) and headers. You need it only to compile CUDA code yourself, for example some custom kernels or packages built from source. Chapter 1.6

D

2D rotation by angle θ
the matrix [[cos θ, −sin θ], [sin θ, cos θ]]. Rotating by θ₁ then θ₂ is rotating by θ₁ + θ₂, and Rᵀ(θ) = R(−θ). Chapter 1.8
Data-parallel attention (attention DP)
Each GPU runs full attention for its own subset of requests and holds only their KV cache, while MoE layers use expert parallelism across the same GPUs. Avoids KV duplication for MLA. Chapter 4.5
Data parallelism
each GPU holds a copy of the model and processes different data; gradients are averaged with all-reduce. Chapter 7.7
DCGM (Data Center GPU Manager)
NVIDIA's tool for GPU health and performance metrics, exported to Prometheus with dcgm-exporter. Chapter 6.6
Decode
The phase that makes output tokens one at a time, each step reading all weights and the KV cache. Usually memory-bound. Chapter 2.4
DeepEP
DeepSeek's library of all-to-all dispatch and combine kernels for expert parallelism over NVLink and RDMA. Version 1 had high-throughput (prefill) and low-latency (decode) kernels; version 2 unified them in one EPBuffer interface. Chapter 4.5
Delta rule
A linear-attention update that first reads what the state returns for a key and writes only the difference, so new information replaces old along that key. Gated DeltaNet adds a forgetting gate. Chapter 2.7
Derivative
how much an output changes when you change one input by a tiny amount. If dL/dw = 3, increasing w by 0.001 increases L by about 0.003. Chapter 1.5
Disaggregated serving
prefill and decode run on separate engines, usually separate GPUs or nodes. Chapter 4.6
Distillation
training a smaller student to imitate a larger teacher (chapter 7.5). Chapter 7.1
DPO (Direct Preference Optimization)
Preference tuning on chosen and rejected answer pairs with a classification loss against a frozen reference model; no reward model and no sampling during training. Chapter 7.4
Drafter (speculator, proposer)
anything that cheaply guesses the next tokens: a small model, extra heads, or a lookup in earlier text. Chapter 4.3
Draft length k
how many tokens are guessed per round (vLLM: num_speculative_tokens). Chapter 4.3
Driver
the low-level software that talks to the GPU. It is installed on the machine by the provider. It sets the highest CUDA version you can use. Chapter 1.6
DSpark
DeepSeek-V4.1-Flash's speculative decoding module: a three-block drafter that proposes five tokens, plus a confidence head whose predicted acceptance rates decide how many drafts each request verifies. Chapter 4.8

E

E2E (end-to-end latency)
the full request time. Chapter 2.4
EAGLE
A speculative decoding drafter: a small head that predicts the next tokens from the target model's own hidden states. Chapter 4.3
Element
one item in a vector. In code, v[0] is the first element. Chapter 1.1
Embedding
The learned vector for a token ID, looked up from the embedding table at the start of the model. Chapter 2.1
Embedding model (bi-encoder)
a model that maps one text to one vector; query and document are encoded separately and compared by cosine similarity, so documents can be embedded once, offline. Chapter 8.1
Encode / decode
text to IDs, and IDs back to text. Chapter 2.1
Entropy
H(p) = −Σ p(x) log p(x), the average surprise of outcomes drawn from p; zero when one outcome is certain, largest when all are equally likely. With natural logs the unit is nats; with log base 2, bits. Chapter 1.7
EPLB (expert-parallel load balancer)
DeepSeek's algorithm for choosing which experts to replicate and where: a hierarchical policy (expert groups to nodes, then within nodes) for prefill and a global policy for wide decode. Chapter 4.5
Erlang C
The queueing formula for c identical servers with random arrivals, used to estimate waiting time at a given utilization. Chapter 6.4
Error budget
the failures the SLO allows (here 1% of requests). Chapter 6.6
Evidence label
a tag on every number: measured (you ran it, with the config and raw data), simulated (from a model or simulator you built, with its assumptions), estimated (arithmetic from specifications), or quoted (from a source, with the reference). Chapter 8.5
Evolution strategies (ES)
Gradient-free optimization that evaluates a population of randomly perturbed models and moves toward the better ones; EGGROLL makes the perturbations low rank. Chapter 7.7
Expectation (mean)
the probability-weighted average of its values, E[X] = Σ x × P(X = x). Expectation is linear: E[X + Y] = E[X] + E[Y] even when X and Y depend on each other. Chapter 1.7
Expert parallelism
Placing different experts of a mixture-of-experts model on different GPUs and sending each token to the GPUs that hold its chosen experts. Chapter 4.5
Exponent bits
set the power of 2, so they set the range: how big and how small a number can be. Chapter 1.3

F

FlashAttention
An attention kernel that computes attention in tiles held in on-chip memory, never writing the full score matrix to HBM. Same result, far less memory traffic. Chapter 2.2
Flash-Decoding (split-KV attention)
Decode attention that splits the KV sequence into chunks processed in parallel and then merges the partial results, so one query can keep the whole GPU busy. Chapter 4.2
Forward and reverse KL
KL(teacher ‖ student) penalizes the student for missing teacher probability (mode covering); KL(student ‖ teacher) penalizes it for putting probability where the teacher would not (mode seeking). Chapter 7.5
FP8
8-bit floating point (E4M3 or E5M2). Used for weights, activations or the KV cache on GPUs with FP8 tensor cores (Ada, Hopper, Blackwell). Chapter 1.3
Free pool
the list of physical blocks not used by any request. Chapter 3.3

G

Gang scheduling
start all parts of a multi-node job together or none of them, so half a model never sits waiting for the other half. Chapter 6.7
General benchmark
a public test of broad ability (instruction following, maths, knowledge), used here to catch regressions. Chapter 7.6
Generation stall
A pause in ongoing decodes while a whole new prefill runs in one iteration; chunked prefill removes it. Chapter 8.4
GGUF
The single-file model format used by llama.cpp, holding weights (often quantized) and metadata such as the tokenizer and chat template. Chapter 3.1
Global KV
the KV cache of attention that spans the whole context (in DeepSeek-V4 and later, the compressed main KV plus the lightning indexer's keys). Its size grows with the sequence length and it lives in HBM while a request runs. Chapter 4.8
Goodput
the rate of requests that meet their latency targets (SLOs), as opposed to total throughput. Chapter 1.10
GPTQ
A post-training weight quantization method that rounds weights one column at a time and adjusts the remaining weights to compensate for each rounding error, using second-order information from calibration data. Chapter 4.1
GPU confidential computing
a GPU mode (from NVIDIA Hopper onwards) that protects the GPU's memory and encrypts traffic between the confidential VM and the GPU over PCIe. Chapter 6.7
GQA (grouped-query attention)
Attention where groups of query heads share one key head and one value head, which shrinks the KV cache by the group factor. Chapter 2.2
Graceful draining
Stopping new requests to a replica while letting in-flight ones finish before it shuts down. Chapter 6.2
Gradient
the list of derivatives of the loss with respect to every parameter. Chapter 1.5
Gradient descent
move each weight a small step against its gradient: w ← w − (learning rate × dL/dw). Chapter 1.5
Grid
all the blocks of one kernel launch. Chapter 5.3 covers this programming model. Chapter 5.2
GRPO (Group Relative Policy Optimization)
An RL method that samples a group of answers per prompt and uses each answer's reward minus the group mean (divided by the spread) as its advantage, with no value model. Chapter 7.4

H

Harness
the software around the model that runs the loop: prompts, tool handling, context management, sub-agents, hooks. Chapter 6.8
HBM
the GPU's main memory. Large (80 GB on an H100) but comparatively slow (about 3.35 TB/s). Chapter 4.2
HBM (high-bandwidth memory)
The GPU's main memory. Its bandwidth (for example about 3.35 TB/s on an H100 SXM) sets the decode speed limit. Chapter 2.4
Heavily Compressed Attention (HCA)
V4's second attention type, which compresses the KV of every m′ tokens into one entry (m′ = 128) and attends densely to all of them, with no sparse selection. Chapter 4.8
Hessian
the matrix H of second derivatives of the loss with respect to the weights. It describes curvature: how fast the loss rises when weights move in each direction. Chapter 1.8
histogram_quantile
The PromQL function that estimates a percentile from histogram buckets by linear interpolation inside the bucket that holds it. Chapter 6.6
Host / device
the CPU and its memory / the GPU and its memory. Chapter 5.3

I

Image
an immutable package built from a Dockerfile, made of layers. Chapter 6.2
Incident commander
The person who holds the overall state of an incident, assigns roles and makes decisions. Chapter 6.9
IO-aware algorithm
one designed around the cost of moving data between memory levels, not just the number of FLOPs. Chapter 4.2
ITL (inter-token latency)
the time between two specific tokens. TPOT is the mean of the ITLs. Benchmarks report ITL percentiles to show jitter. Chapter 2.4

K

Kernel fusion
Combining several operations into one GPU kernel so intermediate results stay on chip instead of making round trips through HBM. Chapter 5.4
Key (k)
what this token offers to be found by. Compared with queries. Chapter 2.2
Key (K) and value (V) vectors
from 2.2, each attention layer turns each token into a query, a key and a value. A token's query asks "which earlier tokens matter to me?". Every token's key answers "this is what I contain". Every token's value is "this is what I pass on if you attend to me". Chapter 2.4
KL divergence
KL(p‖q) = Σ p(x) log(p(x) ÷ q(x)) = CE(p, q) − H(p), the extra surprise caused by using q instead of p. It is never negative and is zero only when q = p. Chapter 1.7
KV cache
Stored key and value vectors of every past token in every layer, so each new token step computes only the new token's keys and values. Chapter 2.4
KV cache quantization
the stored keys and values use fewer bits (often FP8), independent of the weights. Chapter 4.1
KV eviction (H2O, SnapKV)
Dropping the KV entries of tokens that receive little attention, to bound memory at long context. Unlike paging, the dropped information is lost. Chapter 4.7
KV offloading (tiered KV cache)
Keeping KV blocks that do not fit, or are idle, in CPU memory, local disk or a remote store, and loading them back instead of recomputing them. Chapter 4.4

L

LeaderWorkerSet
A Kubernetes API that treats a leader pod and its worker pods as one replica, for models sharded across nodes. Chapter 6.7
Learning rate
the step size. Too small: training is slow. Too large: the loss jumps around or explodes. Chapter 1.5
Lightning attention
MiniMax's blockwise linear attention, which passes the running state between blocks of tokens; used in 7 of every 8 layers of MiniMax-01 and M1. Chapter 2.7
Lightning indexer
A small, cheap scoring network in DeepSeek Sparse Attention that scores every earlier token (or compressed entry) for each query, so real attention runs only on the top-k. Can run in FP8 or FP4. Chapter 4.2
Little's law
in any stable system, the average number of requests inside (L) equals the arrival rate (λ) times the average time each spends inside (W): L = λW. It needs no assumption about distributions. Chapter 1.10
LLM-as-a-judge
using a model to score outputs against a rubric or to compare two outputs. Chapter 7.6
Log
a timestamped record of one event, such as a request finishing or a configuration change. Shows what happened in detail. Chapter 6.6
Logit
the raw score the model gives one token. It can be any real number. A higher logit means "more likely next". Chapter 1.2
Logit distillation
train the student to match the teacher's full next-token distribution (or its top-k) at each position, instead of only the sampled token. More signal per token; needs teacher logits and a shared tokenizer. Chapter 7.5
LoRA
A fine-tuning method that trains two small low-rank matrices per adapted weight instead of the full weight. Serving engines can load many LoRA adapters over one base model. Chapter 3.5
LoRA (low-rank adaptation)
keep the pretrained weight W (d × k) frozen and learn an update ΔW = B × A, where B is d × r and A is r × k with a small rank r. The layer computes W x + (α ÷ r) × B (A x). Chapter 7.3
Loss mask
a per-token flag that says whether a token's prediction counts in the loss. Masked tokens get the label -100 in PyTorch and Hugging Face code. Chapter 7.2

M

Mantissa bits
(also called fraction or significand): set the digits after the binary point, so they set the precision: how finely you can tell two nearby numbers apart. Chapter 1.3
Matrix
a 2-D grid of numbers with rows and columns. A matrix with m rows and n columns has shape [m, n]. Chapter 1.1
MBU (model bandwidth utilization)
Achieved memory bandwidth ÷ peak bandwidth during decode. Measures how close decode gets to the memory floor. Chapter 2.5
MCP (Model Context Protocol)
An open standard for connecting models and agents to tools and data sources. Chapter 6.8
Memory-bound
An operation whose time is set by how fast bytes move from memory, not by arithmetic. Small-batch decode is the main example. Chapter 2.5
Memory-bound (bandwidth-bound)
moving bytes between GPU memory (HBM) and the chip is the bottleneck. Time ≈ bytes ÷ bandwidth. Fewer bytes (fusion, quantization, batching) or more bandwidth helps. Chapter 5.1
Merging
adding (α ÷ r) × B × A into W after training, giving a normal model with no extra cost at inference. Chapter 7.3
Metric
a number sampled over time, such as requests per second or KV cache usage. Cheap to store and aggregate; shows that something changed. Chapter 6.6
MFU (model FLOPs utilization)
useful model FLOPs per second ÷ the GPU's peak (chapter 2.5), the main efficiency score for training. Chapter 7.7
Mid-training (continued pretraining)
more next-token training on a targeted corpus, such as code, long documents or a company's documents, to add knowledge or context length. Chapter 7.1
MIG (Multi-Instance GPU)
Partitioning one NVIDIA data-center GPU into isolated slices, each with its own memory and compute. Chapter 5.5
MLA (multi-head latent attention)
Attention that caches one small compressed latent vector per token per layer instead of full keys and values, then expands it when needed. Used by DeepSeek V2 and V3. Chapter 2.4
M/M/1 queue
the simplest queue model: random (Poisson) arrivals, random (exponential) service times, one server. Its average time in the system is W = 1 ÷ (μ − λ). Chapter 1.10
MoE (mixture of experts)
A model whose feed-forward layers hold many experts; a router sends each token to a few of them. Memory follows total parameters; compute follows active parameters. Chapter 2.6
Momentum
keep a running average m ← μm + g and step along m, which smooths noisy gradients. Chapter 1.9
MQA (multi-query attention)
Attention in which all query heads share one key head and one value head, shrinking the KV cache by the number of heads. Chapter 4.2
MTP (multi-token prediction)
Extra prediction heads trained with the model to predict several future tokens; at inference they can serve as a built-in drafter. Chapter 4.3
MTTF (mean time to failure)
Average time between failures; for a group of nodes, 1 ÷ (nodes × failure rate per node). Chapter 6.9
Multi-LoRA serving
Serving many LoRA adapters on one base model in the same batches, fetching adapters to the GPU as requests need them. Chapter 7.6
Muon
An optimizer for hidden-layer weight matrices that orthogonalizes the momentum update with a few Newton-Schulz iterations. Chapter 7.7

N

Negative result
a change that did not help, or helped in one regime and hurt in another; it is reported, not dropped. Chapter 8.5
NF4 and double quantization
QLoRA's 4-bit NormalFloat format for normally distributed weights, and the quantization of its block scales to cut their overhead to about 0.127 bits per parameter. Chapter 7.3
NIXL
NVIDIA's inference transfer library for moving KV blocks between engines and memory tiers; used by Dynamo and by vLLM's NixlConnector. Chapter 4.6
NVFP4
NVIDIA's 4-bit floating-point format for Blackwell GPUs, with a scale factor per block of 16 values. Chapter 1.3
NVIDIA Container Toolkit
lets containers use the host's GPUs and driver. The host driver must be new enough for the CUDA version inside the image (chapter 1.6). Chapter 6.2

O

Occupancy
The share of an SM's maximum resident warps that are actually resident. Enough occupancy hides memory latency; more is not always faster. Chapter 5.2
Off-policy (sequence-level) distillation
SFT on answers sampled from the teacher. Simple, works with API-only teachers. Chapter 7.5
Online softmax
Computing softmax in one pass over blocks of scores by keeping a running maximum and running sum and rescaling earlier partial results. The basis of FlashAttention. Chapter 4.2
On-policy distillation
the student samples answers; the teacher computes its log-probabilities on the student's tokens; the per-token difference is the training signal. Chapter 7.5
OpenAI-compatible API
An HTTP API that copies OpenAI's chat completions and completions endpoints, so the same client code works with vLLM, SGLang and other servers. Chapter 3.1
Open-loop and closed-loop load
Open loop: requests arrive on a schedule (for example at a fixed rate) whatever the server does. Closed loop: a fixed number of clients each wait for a reply before sending again, which hides overload. Chapter 6.1
Ops:byte ratio
(of hardware): peak FLOP/s ÷ peak bytes/s. How many FLOPs the GPU can do in the time it reads one byte. Chapter 2.5
Orchestrator (scheduler)
software that decides which job or service runs on which machines, starts it, and restarts it on failure. Chapter 6.7
Orthogonal matrix
a square matrix Q with QᵀQ = I. Multiplying by it preserves lengths and dot products: (Qx)·(Qy) = x·y. Rotations and reflections are orthogonal. Chapter 1.8
Overhead-bound
the GPU waits for work. Time goes to the Python interpreter, framework dispatch, kernel launches, or the CPU waiting for a result from the GPU. Fewer, larger kernels (fusion, CUDA graphs, compilation) and less CPU work help. Chapter 5.1
Overlong penalty
A reward term that penalizes answers beyond a length threshold, used to stop RL from inflating answer length. Chapter 7.4

P

Packing
concatenating several short examples into one training sequence up to a maximum length, so batches contain no padding. Chapter 7.2
PagedAttention
Storing the KV cache in fixed-size blocks anywhere in GPU memory, with a block table per request, and an attention kernel that reads through the table. Removes most fragmentation. Chapter 3.3
Parameters
all weights and biases together. "8B parameters" counts these. Chapter 1.5
Pareto curve (throughput vs interactivity)
An engine's throughput per GPU plotted against tokens per second per user across concurrency levels; a curve above and to the right is better at every operating point. Chapter 6.10
Percentile
the p-th percentile (p50, p95, p99) is the value below which p% of measurements fall. p50 is the median. Chapter 1.10
Per-channel and group-wise scales
One quantization scale per output channel, or per group of consecutive weights (for example 128). Smaller groups follow outliers better at the cost of storing more scales. Chapter 4.1
Perplexity
e raised to the cross-entropy per token; the number of equally likely choices that would be as confusing as the model is. Chapter 1.7
Persistent KV
the part of the KV cache stored after a request ends (on SSD or in host memory) so later requests with the same prefix can skip prefill (chapter 4.4). Chapter 4.8
Piecewise CUDA graphs
Capturing CUDA graphs for the parts of a model step between operations that cannot be captured (such as some attention kernels), as vLLM does. Chapter 5.7
Ping-pong pipelining
Splitting a batch into micro-batches that alternate between an attention pool and an expert pool so both stay busy, as in MegaScale-Infer. Chapter 4.5
Pipeline parallelism
Splitting a model by layers across GPUs or nodes; each stage passes activations to the next. Chapter 4.5
Pod
Kubernetes' unit of deployment, one or more containers scheduled together on one node. Chapter 6.7
Policy
the model being trained, viewed as a rule that picks the next token. Chapter 7.4
Pooling
how a sequence of hidden states becomes one vector: the first token's state (CLS pooling, the default for BERT-style encoders), the last token's (LAST, for decoder-style embedding models) or the mean over all tokens (MEAN). Chapter 8.1
Power of two choices
A routing policy: pick two replicas at random and send the request to the less loaded one. Chapter 6.4
Preemption
Pausing a running request when KV memory runs out, by freeing its blocks (recompute later) or copying them to CPU memory (swap). Chapter 3.2
Preference optimization
training on pairs of answers labelled better and worse, so the model shifts probability toward the better kind (DPO and relatives, chapter 7.4). Chapter 7.1
Prefill
The phase that processes the whole prompt in one parallel pass and writes its KV cache. Usually compute-bound; sets TTFT. Chapter 2.4
Prefix caching
Keeping the KV blocks of earlier requests and reusing them when a new request starts with the same tokens, skipping their prefill. Chapter 3.5
Pretraining
training on a very large text corpus to predict the next token. Produces a base model with knowledge and skills but no assistant behaviour. Chapter 7.1
Probability distribution
a list of non-negative numbers that add up to 1. Each number is the chance of one outcome. Chapter 1.2
Programmatic tool calling
The model writes code that calls tools inside a sandbox and returns only the processed result to the context. Chapter 6.8
Prompt-completion dataset
each example is one prompt and one target completion. Chapter 7.2
PTQ (post-training quantization)
quantize a finished model, using at most a small calibration set. Chapter 4.1

Q

QAT (quantization-aware training)
train with the low precision simulated, so the weights adapt to it. Chapter 4.1
QK-Clip
Kimi K2's fix for Muon training instability: after each update, rescale the query and key projection weights so attention logits stay bounded (MuonClip). Chapter 7.7
Quantization
Storing weights, activations or the KV cache in fewer bits (for example INT8, FP8, INT4) to cut memory and bandwidth, at some accuracy risk. Chapter 1.3
Query (q)
what this token is looking for. Chapter 2.2

R

Radix tree (prefix tree)
A tree keyed by token sequences. SGLang's RadixAttention uses it to find the longest cached prefix of a new request. Chapter 3.5
Random variable
a quantity whose value depends on chance, such as the number of draft tokens accepted in one speculative step. Chapter 1.7
Rank
the number of independent directions a matrix can output; an m × n matrix of rank r can be written as the product of an m × r and an r × n matrix. Chapter 1.8
Readiness and liveness probes
Health checks: liveness asks whether the process should be restarted; readiness asks whether it can receive traffic now. Chapter 6.2
Redundant experts
Extra copies of frequently used MoE experts placed on other GPUs, so no single GPU becomes the straggler under expert parallelism. Placed by observed load (EPLB). Chapter 4.5
Reference model
a frozen copy of the starting policy (usually the SFT checkpoint). A KL penalty keeps the policy's probabilities close to it. Chapter 7.4
Registers
the fastest storage, private to each thread. Chapter 5.2
Registry
where images are stored and pulled from. Chapter 6.2
Regression check
a fixed set of evaluations every new checkpoint must not get worse on. Chapter 7.6
Remote attestation
a signed report, produced by the hardware, of exactly what was booted and loaded. A client checks it against known-good values before sending data. Chapter 6.7
Reranker (cross-encoder)
a model that reads a query and one document together and outputs a single relevance score; it is more accurate than comparing vectors but must run once per query-document pair. Chapter 8.1
Reserved, on-demand and spot capacity
GPU purchasing models: committed blocks at a discount; pay-as-you-go up to a quota; discounted spare capacity that can be reclaimed at short notice. Chapter 6.5
Retry budget
A limit on retries per request and across the fleet, so that a partial outage does not turn into a retry storm. Chapter 6.9
Reward hacking
The policy finds outputs that score highly under the reward but are not what was wanted, such as padding answers to earn a length-correlated reward. Chapter 7.4
Reward model
a model trained on human comparisons ("A is better than B") to output a score for an answer. Chapter 7.4
Ring all-reduce
a common algorithm in which each GPU sends and receives about 2 × (n − 1) ÷ n times the tensor size. NCCL (NVIDIA) and RCCL (AMD) are the libraries that implement collectives. Chapter 4.5
Ring attention
Context-parallel attention in which GPUs pass blocks of keys and values around a ring while each computes attention for its own queries. Chapter 4.7
RLHF and RLVR
RL from human feedback (a reward model trained on human comparisons) and RL with verifiable rewards (automatic checks such as unit tests or exact maths answers). Chapter 7.1
RL (reinforcement learning)
the model generates answers, a reward scores them, and training raises the probability of high-reward answers. RLHF uses a reward model trained on human preferences; RLVR uses verifiable rewards such as unit tests or checked maths answers. Chapter 7.1
RMSNorm
A normalization layer that divides a vector by its root mean square and multiplies by learned gains. Used instead of LayerNorm in most current LLMs. Chapter 1.5
Rollout
one answer the policy generates during training. Chapter 7.4
Roofline
A plot of attainable FLOP/s against arithmetic intensity: a sloped memory roof and a flat compute roof meeting at the ops:byte ratio. Chapter 2.5
RoPE (rotary position embedding)
Encoding position by rotating each pair of query and key dimensions by an angle proportional to the token's position, so attention scores depend on relative distance. Chapter 2.3
RULER
A long-context benchmark of synthetic retrieval, tracing and aggregation tasks at controlled lengths, used to measure the context a model really handles. Chapter 4.7
Run-to-run deterministic
the same kernel on the same inputs gives bitwise identical outputs every time. True for most inference kernels. Chapter 6.6

S

safetensors
A simple, safe file format for tensors (a JSON header plus raw bytes), the standard for Hugging Face model weights. Chapter 3.1
Sampling (temperature, top-k, top-p)
Picking the next token from the probability distribution. Temperature sharpens or flattens it; top-k keeps the k most likely tokens; top-p keeps the smallest set whose probabilities reach p. Chapter 1.2
Scalar
one number, for example 0.7. Chapter 1.1
Scale to zero
Removing all replicas of an idle deployment, accepting a cold start for the next request. Chapter 6.3
Scale-up domain
the set of GPUs connected by the fast in-node or in-rack fabric (NVLink, or Huawei's unified bus); a supernode is a large one, such as a 64-GPU or 72-GPU rack. Chapter 4.8
Second-order approximation
near a trained minimum the gradient is about zero, so changing the weights by e raises the loss by about ½ eᵀHe. Chapter 1.8
Selective batching
Orca's technique of batching the operations that ignore sequence boundaries (linear layers over a flat token list) while running attention per request; the basis of continuous batching. Chapter 3.2
SFT (supervised fine-tuning)
training on example conversations so the model imitates the assistant's replies. Chapter 7.1
Shape
the size of each dimension, written as a list. [2, 8, 4096] means 2 × 8 × 4,096 numbers. Chapter 1.1
Shared memory (SMEM)
fast on-chip memory shared by the threads of one block. Chapter 5.2
Sign bit
0 for positive, 1 for negative. Chapter 1.3
Singular value decomposition (SVD)
any matrix W = U Σ Vᵀ, with U and V orthogonal and Σ diagonal with non-negative singular values in decreasing order. Each singular value says how much W stretches one direction. Chapter 1.8
Sliding-window attention
Attention where each token sees only the last W tokens, which caps that layer's KV cache at W tokens. Chapter 2.2
SLI (service level indicator)
a measured quantity users care about, such as the share of requests with TTFT under 1 s. Chapter 6.6
SLO (service level objective)
the target for it, such as 99% over 30 days. Chapter 6.6
Slot mapping
The position of each token's keys and values in a paged KV cache: block table entry p // block size, offset p % block size. Chapter 8.3
SmoothQuant
Moves the difficulty of quantizing activations into the weights: divides activation outliers by a per-channel factor and multiplies the matching weights by it, so both can be stored in 8 bits. Chapter 4.1
SM (streaming multiprocessor)
The GPU's unit of execution: it holds tensor cores, registers and shared memory, and runs thread blocks. Chapter 5.2
Softmax
The function that turns a list of logits into probabilities: exponentiate each, then divide by the sum. Chapter 1.2
Speculative decoding
A cheap draft proposes several tokens; the big model checks them all in one pass and keeps the accepted ones. Output distribution is unchanged; latency drops when acceptance is high. Chapter 2.7
Split-K
A matmul strategy that splits the reduction dimension across thread blocks and adds the partial results, used when the output is too small to keep the GPU busy. Chapter 5.8
SRAM (shared memory)
small, fast memory inside each streaming multiprocessor (SM), up to about 228 KB per SM on an H100, which has 132 SMs. Its total bandwidth is roughly an order of magnitude higher than HBM. The FlashAttention paper quotes about 19 TB/s for the A100's SRAM against 1.5 to 2.0 TB/s for its HBM. Chapter 4.2
State space model (linear attention, Mamba)
A layer that keeps a fixed-size state per sequence instead of a growing KV cache. Constant memory and per-token cost; weaker exact recall. Chapter 2.7
Stream
an ordered queue of GPU work. Work in one stream runs in order; work in different streams may overlap. PyTorch uses one default stream per device unless told otherwise. Chapter 5.3
Strong baseline
the best reasonable configuration of a standard system (for example a current engine with sensible flags), not a deliberately weak one. Chapter 8.5
SWA bounded replay
rebuilding a missing sliding window KV state approximately by recomputing only the last nwin tokens (128) and truncating the window to that replayed segment, instead of the nwin × L tokens an exact rebuild needs. Chapter 4.8
Synchronization
the CPU waits until the GPU has finished queued work. Explicit (torch.cuda.synchronize()) or implicit (any operation that needs a GPU value on the CPU). Chapter 5.3

T

Tail latency
the high percentiles, which describe the slowest requests rather than the typical one. Chapter 1.10
Target model
the model whose output you want. Its output decides everything. Chapter 4.3
Target modules
the linear layers that get adapters, such as the attention projections (q, k, v, o) and the MLP projections (gate, up, down). Chapter 7.3
Task evaluation
a held-out set from your real use case, scored the way the product needs (exact field match, unit tests passing, a rubric). Chapter 7.6
Teacher and student
the larger model whose behaviour is copied, and the smaller model being trained. Chapter 7.5
TEE (trusted execution environment)
Hardware-protected execution whose memory the host cannot read, with attestation to prove what is running. Chapter 6.7
Tensor
a grid of numbers with any number of dimensions. A scalar has 0, a vector 1, a matrix 2. LLM code uses 3-D and 4-D tensors all the time. Chapter 1.1
Tensor core
A GPU unit that multiplies small matrix tiles in one instruction, providing most of the GPU's FLOPs for matmuls. Chapter 5.2
Tensor parallelism
Splitting each weight matrix across GPUs so every GPU computes part of every layer, with all-reduce communication after each split layer. Chapter 2.5
Thinking budget
A per-request cap on reasoning tokens, after which the engine forces the end of the thinking section. Chapter 8.1
Thread
one instance of a kernel's code with its own registers. Chapter 5.2
Thread block (CTA)
a group of threads (up to 1,024) that run on one SM and can share its shared memory and synchronize with each other. Chapter 5.2
Throughput
Tokens produced per second across all requests on a server or GPU. Chapter 2.4
Tiling
Splitting a matmul or attention into tiles that fit in shared memory and registers, so each value loaded from HBM is reused many times. Chapter 5.8
Token
one piece of text in the tokenizer's vocabulary. Chapter 2.1
Token ID
the integer for a token. The model only ever sees IDs. Chapter 2.1
Token step
one run of the model that makes one new token for one sequence. Chapter 2.4
Tool call
a structured request from the model, such as {"name": "shell_run", "arguments": {...}}, which the program executes; the result (the observation) is added to the context. Chapter 6.8
torch.compile
PyTorch's compiler: captures the model as a graph and generates fused kernels for it. Chapter 5.7
Total parameters
every weight in the model, including all experts. Sets memory. Chapter 2.6
TPOT (time per output token)
the average time between output tokens after the first. It is set by decode step time. Longer context and a bigger batch make it longer. Chapter 2.4
Trace
the path of one request through the system, as a tree of timed steps called spans (gateway, queue, prefill, decode). Shows where the time went. Chapter 6.6
Train-inference mismatch
Differences between the probabilities a trainer computes and those the inference engine sampled with, from different kernels, templates or precision. Chapter 7.6
Trajectory
the full sequence of model calls, actions and observations for one task. Chapter 6.8
Transpose
the same matrix with rows and columns swapped. Shape [m, n] becomes [n, m]. Written Aᵀ, or A.T in code. Chapter 1.1
Triton
A Python-embedded language and compiler for writing GPU kernels at the level of blocks of data rather than individual threads. Chapter 5.4
TTFT (time to first token)
from request arrival to the first output token. It includes queue time and prefill. Long prompts make TTFT longer. Chapter 2.4

U

Utilization
ρ = λ ÷ μ, arrival rate over service capacity. Chapter 1.10

V

Value (v)
the information this token passes on when another token attends to it. Chapter 2.2
Variance
the expected squared distance from the mean, Var[X] = E[(X − E[X])²]; its square root is the standard deviation. Chapter 1.7
Vector
an ordered list of numbers, for example [0.2, −1.3, 0.5]. The number of items is its dimension or length. Chapter 1.1
VE/prefill/decode disaggregation (EPD)
Running the vision encoder, prefill and decode of a multimodal model as three separately scaled pools. Chapter 4.6
Verification
one target forward pass over the k draft tokens. Chapter 4.3
Vocabulary
the full list of tokens the model knows. Chapter 2.1 explains how text becomes tokens. Chapter 1.2

W

Warp
32 threads that execute the same instruction together (SIMT: single instruction, multiple threads). Chapter 5.2
Weight-and-activation quantization
both matmul inputs are in low precision, so the tensor cores run the low-precision instruction. Chapter 4.1
Weight matrix
a matrix of learned numbers inside a model layer. Chapter 1.1
Weight-only quantization
weights are stored in low precision and converted back (dequantized) to 16-bit inside the matmul kernel. The math runs in 16-bit. Chapter 4.1
Weight (w)
a learned number that says how much one input matters. Chapter 1.5
Wide-EP
Expert parallelism over a large group (for example 64 to 128 GPUs in one supernode) for decode, so each expert sees enough tokens and each GPU reads fewer expert weights. Chapter 4.8
WxAy
weights stored in x bits, activations (the inputs to each matmul) in y bits. W4A16 is weight-only quantization; W8A8 quantizes both. Chapter 4.1

X

Xid error
An error code from the NVIDIA driver in the kernel log, identifying GPU faults such as memory errors or a GPU falling off the bus. Chapter 6.9
xPyD
Shorthand for a disaggregated deployment with x prefill workers and y decode workers. Chapter 4.6

Z

ZeRO and FSDP (fully sharded data parallelism)
data parallelism that shards optimizer state (ZeRO-1), also gradients (ZeRO-2), and also the weights themselves (ZeRO-3, FSDP) across the GPUs, gathering weights just in time for each layer. Chapter 7.7
Zero-computation expert
An MoE routing slot that returns its input unchanged at no cost, so the number of real experts (and active parameters) varies per token, as in LongCat-Flash. Chapter 2.6
Zero point
An offset stored with a quantization scale so that an asymmetric range of values (for example −0.2 to 1.5) maps onto the integer grid without wasting levels. Chapter 4.1
