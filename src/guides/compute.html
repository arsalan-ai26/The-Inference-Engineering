A practical free setup for this book
  1. Use Colab for short labs. Save notebooks to Drive; expect to re-install packages each session.
  2. Use Kaggle for longer runs (12-hour sessions) and two-GPU tests (T4 ×2).
  3. Use Modal's monthly credit for a few hours on a modern GPU (L4, A10 or better) when a lab needs Ampere or newer.

Types of provider

  • Marketplaces (for example Vast.ai): many hosts, lowest prices, variable reliability and network. Good for labs.
  • GPU clouds (for example RunPod, Lambda, Hyperstack, Nebius, CoreWeave): standard machines by the hour with SSH. Good for multi-GPU labs and benchmarks.
  • Serverless (for example Modal, Baseten): pay per second for code or endpoints; no machine to manage.
  • Hyperscalers (AWS, Google Cloud, Azure): integrated with everything else, usually higher on-demand prices, quotas to request.

4. From $/hour to $ per million tokens

tokens per hour = tokens per second × 3,600 × utilization
$ per million tokens = price per hour ÷ tokens per hour × 1,000,000
Interactive: cost per million tokens
Use chapter 2.5's throughput estimate (or a measurement) for tokens per second. Utilization is the share of each hour the GPU does useful work; idle time still costs money.
Worked example

Llama 3.1 8B on one H100 at batch 32 with 8K contexts: at most about 2,130 tokens per second (chapter 2.4, Example C; a real engine reaches less). At $2.90 per hour and 60% utilization: 2.90 ÷ (2,130 × 3,600 × 0.6) × 10⁶ ≈ $0.63 per million output tokens. At batch 1 (at most about 209 tokens per second) the same GPU costs about $6.42 per million. Batching is the cost lever.

6. Avoiding surprise bills

  • Set a spending limit or prepaid balance where the provider allows it.
  • Stop or delete machines when you finish; check the billing page afterwards (chapter 1.6, lab Part D).
  • Persistent disks and volumes may bill while the machine is off. Delete what you do not need.
  • Download models to the machine's local disk once per session instead of re-pulling them on every restart.
  • Prefer spot or interruptible instances only for work you can restart.
